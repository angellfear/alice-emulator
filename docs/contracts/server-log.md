# Журнал сервера

Код: `server_emulator/server_log.py`.

## Обзор

Журнал событий и ошибок сервера для администратора.

## Журнал

Хранилище — `server_emulator/server_log.py`, SQLite `state/server_log.sqlite3` (WAL, очередь +
фоновая запись через aiosqlite в цикле событий, вызов `log()` диска не ждёт; sync-соединение —
только для кода без цикла: старт процесса, инструменты, тесты). Запись: `level`
(info/warning/error), `source`
(короткий код: server, tls, http, ws, upstream, quasar, extensions, scripts, scenarios, updates,
self_update, auth), `message` (первая строка, на русском, без секретов), `device_sn`, `detail`
(отдельные поля: хост, путь, код, причина; заголовки и тела не передаются). Повторы в пределах
часа с тем же (level, source, message, device_sn) склеиваются: счётчик `count` и время последнего
случая `last_ts` вместо новой строки — ошибки на каждом соединении не забивают журнал. Хранение —
3 суток и не больше 100 000 строк; чистка при старте и раз в час.

Что пишут: обработчик `logging` (WARNING+ от `aiohttp.server`/`aiohttp.access`/`asyncio`/
`server_emulator.*`, source по имени логгера, сообщение — первая строка исключения без трейсбека —
сюда попадают `LineTooLong` aiohttp); вызов с `extra={"journal_detail": {...}}` добавляет эти
поля в `detail` записи (например, голосовой стек кладёт туда полный хвост вывода неудачной
установки — `voice_stack.LocalSpeech`, сообщение остаётся одной строкой с причиной, весь вывод
есть и в `install.log` пакета); точечные записи там, где и `runtime.recent` (замены regexp
сломали JSON — quasar, ошибки обработчиков эндпоинтов — scripts, сбои сценариев — scenarios,
расхождение DeviceId — http/ws), ошибки пересылки наверх 502 (upstream, `upstream/forward.py`);
события сервера: старт (версия, слушатели), остановка/перезапуск, откат настроек слушателей,
самообновление (доступна версия, сбой проверки, запуск обновления/отката, итог от updater'а),
неудачный вход в панель (auth, имя без пароля, IP). Точечные записи дополняют `recent` — на нём
живут другие вкладки. Для кода без runtime — модульные `server_log.log_event()`/`flush()`
(выход сервера дожидается записи очереди).

API `ui/api/server_log.py`: `GET server_log?level=&source=&q=&before=<ts>&limit=200` →
`{items, sources, more}` (новые сверху, `before` — пагинация «Показать ещё», `level` принимает
имена через запятую) и `DELETE server_log` — очистить; только админ. UI — вкладка
«Дополнительно → Лог» (`ui/server_log.js`): фильтры уровня/источника, поиск по тексту, клик по
строке раскрывает `detail`, автообновление раз в 10 с, пока вкладка открыта и документ виден.
