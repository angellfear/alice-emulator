# Quasar-конфиг: встроенный шаблон + замены

## Сборка ответа `/get_sync_info` (режим «Генерируемый»)

```
встроенный шаблон (quasar_defaults: общий дефолт + особенности платформы)
  → общие замены → замены платформы → замены аккаунта → замены устройства
  → динамика ({{токены}} в строках, маркеры db/run) → итог
```

Одна функция — `quasar_rules.compose_config(runtime, platform, device, device_rules, trace,
render)`; ей пользуются ответ колонке, `generate`, просмотр итога в UI. Замены каждого слоя
применяются сверху вниз: нижняя сильнее. Слои расширений идут раньше пользовательских
(сначала расширения, затем свои) и только читаются.

## Замена

```json
{"id": "a1b2c3d4e5", "name": "Подписка", "path": "/subscription", "kind": "select",
 "value": "Включена", "options": {"Включена": {"enabled": true}, "Выключена": {"enabled": false}},
 "enabled": true}
```

- `path` — JSON Pointer (RFC 6901, библиотека `jsonpointer`): ключи с точкой
  (`com.yandex.io.sdk`) адресуются как есть, `/` и `~` экранируются `~1`/`~0`. Пустой путь
  (весь документ) и пустые сегменты запрещены. Недостающие объекты по пути создаются.
- Видов два:
  - `select` — **состояния узла**: `options` — имя → значение, `value` — имя текущего.
    Одно состояние — значение узла; два — переключатель вкл/выкл (первое — «вкл»); три и
    больше — выбор из списка;
  - `delete` — удалить ключ.
- Значение состояния — любой JSON. В строках — подстановки `{{…}}` (см. «Динамика»); строка из
  одной подстановки даёт её значение как есть (число, объект). Маркеры `{"db": "user.<путь>"}` и
  `{"run": "<скрипт>"}` — значение из реестра и stdout скрипта.
- Прежние виды принимаются и переводятся в состояния (`normalize_kind`): `bool` → «Вкл»/«Выкл»
  (`true`/`false`); `value`, `template`, `param` (`"{{ключ}}"`), `db` (`{"db": …}`), `script`
  (`{"run": …}`) — одно состояние «Значение».
- `enabled: false` — замена хранится, но не применяется.
- Проверка — `validate_rules`: нужно хотя бы одно состояние с непустым именем, текущее — из
  списка; ошибка с префиксом `Строка N:` (номер в списке), список не сохраняется. `id` выдаётся
  при сохранении, дубликаты переназначаются.

## Хранение

- Общие: `state/quasar/rules/common.json`, платформы: `state/quasar/rules/platforms/<платформа>.json`
  — `{"rules": [...]}`. Имя платформы — `[a-z0-9_.-]+`, `common` зарезервировано. Файл
  платформы создаётся первым сохранением.
- Устройство: `state.quasar_overrides`; аккаунт: `quasar_overrides` пользователя.
  Прежний формат `{path: "a.b", source}` принимается и переводится в замену при чтении
  (`rules_as_list`): `{"$select": …}` → состояния с вариантами нижних слоёв, `{"delete": true}` →
  `delete`, булево → «Вкл»/«Выкл», остальное (`expr`, `db`, `run`, литерал) — одно состояние.
  Битая запись при сборке пропускается. Запись из UI — всегда новый формат.
- Расширения: `quasar/rules/common.json`, `quasar/rules/platforms/*.json` или прежние тела
  `quasar/common.json`, `quasar/platforms/*.json` (переводятся при чтении).

### Перенос прежних тел

Прежние `state/quasar/common.json` и `platforms/*.json` (тела merge-patch с инлайн-узлами
`$select/$bool/$param/…`) один раз переводятся в замены (`RuleStore.migrate`, при первом
обращении): замена создаётся там, где значение тела отличается от встроенного шаблона хотя бы
одной платформы (общие) или от шаблона платформы с общими заменами (платформа). Итог для колонок
не меняется: `null` в файле платформы колонке не доходил — и после переноса не действует; пустой
объект поверх объекта ничего не меняет. Оригиналы переносятся в `state/quasar/legacy-<дата>/`.

## Динамика

Подстановки `{{…}}` в строках: токены запроса и реестра — `{{now}}`, `{{now_ms}}`, `{{now_iso}}`,
`{{uuid}}`, `{{device_id}}`, `{{device_name}}`, `{{platform}}`, `{{user_id}}`, `{{user.name}}`,
`{{user.location.<ключ>}}`, `{{user.fields.<ключ>}}`, `{{device.room}}`, `{{device.fields.<ключ>}}`;
всё, чего нет среди них, — параметр (`resolve_param`: каталог «Параметры», затем пути реестра).
Внутри текста ненайденная подстановка — пустая строка; строка из одной подстановки — значение как
есть, ненайденный параметр — `QuasarConfigError`, колонке — 409 `quasar_config_source`.
Встроенный шаблон содержит токены и инлайн-узлы — они разрешаются тем же проходом (`resolve_tree`).

Скрипт (`{"run": …}`) — subprocess из белого списка `state/quasar/scripts`, таймаут ~3 с;
переменные окружения QSN/QDEVICE_ID/QUSER_ID/QPATH/QCONTEXT(json); stdout → значение.

`render=False` — сборка без устройства (просмотр «Итог»): подстановки и маркеры остаются как есть,
ошибки «параметр не найден» нет.

## Происхождение значений

`trace` — словарь «путь через точку → подпись»: `общие замены: <имя>`, `замены <платформа>: <имя>`
(с `(<id расширения>)` для слоёв расширений), `аккаунт <пользователь>: <имя>`, `устройство: <имя>`,
`(удалено)` для `delete`; динамика — `динамика {{токен}}`, `БД эмулятора: …`, `скрипт: …`,
`параметр …`. Пути без подписи — из встроенного шаблона.

## API (admin, `/emulator/api/…`, `ui/api/quasar_config_api.py`)

- `quasar_platforms`:
  - `GET` → `{builtin_platforms, common_rules, platforms: [{platform, rules}], devices}`;
  - `GET ?builtin=<платформа>` → встроенный шаблон `{config, keys}` (имя вне белого списка — общий);
  - `GET ?compose=<платформа>` → итог без устройства (`render=False`) с `origins`;
  - `POST {action: "create", platform}`, `POST {action: "rename", platform, to}`,
    `DELETE ?platform=` — файлы замен платформ.
- `quasar_rules`:
  - `GET ?layer=common|platform:<имя>|device:<SN>` → `{rules, inherited}`; `inherited` —
    `[{origin, rules}]` слоёв расширений; для устройства ещё `platform`;
  - `PUT {layer, rules}` — список целиком, после проверки; у устройства пустой список удаляет поле.
- `quasar_composed?device=SN[&raw=1]` → итог устройства `{platform, config, origins, warnings}`;
  `raw=1` — без подстановки (`render=False`), ошибка сборки — `{error}`.

## UI (вкладка «Quasar»)

Слева шаги сборки — «Шаблон», «Общие замены», «Замены платформы», «Замены устройств», «Итог»
(на узком экране — сегменты сверху). Без горизонтальной прокрутки на 400 px.

- «Шаблон» — встроенный шаблон выбранной платформы, только чтение.
- Замены — таблица: галочка вкл/выкл · имя · узел JSON · значение · действия (иконки
  «Редактировать», «Выше», «Ниже», «Удалить»). Значение по числу состояний: одно — кнопка с
  кратким значением (подстановки — теги), два — переключатель, больше — список; переключатель и
  список меняются прямо в строке. Каждое действие сохраняется сразу (`PUT quasar_rules`). Окно
  замены (`<dialog>`): имя, узел (подсказки — пути итога), вид «Состояния | Удалить ключ»,
  список состояний (текущее · имя · значение — текст или JSON), кнопки-теги подстановок
  (токены и параметры каталога) вставляют `{{…}}` в поле значения, «Включена». Замены расширений
  — отдельной группой, только чтение.
- «Замены платформы» — выбор платформы (встроенные и с заменами) и меню платформ.
- «Замены устройств» — список колонок; у выбранной — источник конфига (см. ниже), для
  «Генерируемый» — замены устройства и итог устройства: клик по строке итога — новая замена с
  этим путём.
- «Итог» — сборка без устройства с подсказкой происхождения по наведению.
- Несохранённое состояние есть только у редактора «Свой ответ»; уход с него спрашивает
  подтверждение.

## Замены аккаунта

На настоящем сервере `config` собирается из частей с разными владельцами: `account_config`
(аккаунт), `device_config` (устройство), `system_config` (сервер). Эмулятор повторяет это слоем
замен владельца устройства.

- Пути — только внутри `/config/account_config/` (сам узел целиком не заменяется): иначе
  `QuasarConfigError` при сборке и `ValueError` (HTTP 400) при сохранении.
- Чтение — `GET identities` (`users[].quasar_overrides`); запись — `POST identities`
  `{"operation": "user_quasar_overrides", "id", "quasar_overrides": [...]}`, список целиком,
  пустой — очищает.
- Хранение — meta `identity_user_quasar` (`{user_id: [...]}`); правка имени слой не трогает,
  удаление пользователя удаляет слой. У устройства без владельца слоя нет.
- UI — карточка пользователя, вкладка «Настройки аккаунта».

## Встроенный шаблон

`server_emulator/quasar_defaults/` — полный ответ без захвата, перенесённый из исходников
quasar-server (MIT; commit и пересборка — `tools/build_quasar_defaults.py` и README рядом):

- `common.json` — config (account_config/device_config/system_config) +
  `alice_pro_subscription {enabled: true, ttl: 31536000}` + `subscription {mode: "transaction"}`
  + `tags: []`; `device_config.name` — токен `{{device.name}}`;
- `platforms/<платформа>.json` — merge-patch поверх common для 13 платформ; chiron/magritte —
  `hybrid_request_factory`: `supported_frames` — объект и удаление `hybrid_voice_inputs`.

Платформа шаблона — `device_platform`: `device.profile.platform` → платформа, которую колонка
сообщила при опросе (query `platform`, хранится в `state.reported_platform`) → пусто (общий).

Пока нет ни одной замены (ни своей, ни расширений), устройство с прежним `state.quasar.config`
получает его как есть.

## Источник конфига устройства

Каждое устройство выбирает, откуда брать ответ на `GET /get_sync_info`. Режим хранится в
`state.quasar_source` устройства, свой ответ — в `state.quasar_custom`, последний ответ Яндекса —
в `state.quasar_direct_last` (`{ts, status, body}`, тело — распакованный JSON). Отсутствие поля —
режим `generated`.

| Метка | Режим | Что получает колонка |
|---|---|---|
| **Генерируемый** | `generated` (по умолчанию) | конфиг, собранный `compose_config`: шаблон и замены (см. выше) |
| **Напрямую** | `direct` | ответ настоящего `quasar.yandex.net` без изменений; обмен — в «Журнал» (`source=upstream`) по опции «Запись» устройства; успешный JSON сохраняется в `state.quasar_direct_last` |
| **Свой** | `custom` | `state.quasar_custom` как есть: без замен, инлайн-узлов и подстановки стереопары; нет сохранённого или в нём нет `config` → 409 `quasar_custom_not_set` |

Маршрут API (`ui/api/quasar_config_api.py`, домен `quasar_source`):

- `GET ?sn=` → `{mode, direct_last, custom, replace, transparent, can_fetch}`; `can_fetch` — запомнены ли
  заголовки последнего опроса этой колонки; `replace` — правила замен «Напрямую» (по умолчанию `[]`);
  `transparent` — галочка «И в прозрачном маршруте» (по умолчанию `false`);
- `PUT {sn, mode?, custom?, replace?, transparent?}` — сохранение режима, своего ответа, замен и/или
  галочки под `runtime.lock` (custom — JSON-объект с объектом `config`, иначе 400; `replace` — см.
  ниже; `transparent` — bool, иначе 400);
- `POST {sn, action: "generate"}` — ответ, который собрал бы `compose_config` (как отдаётся колонке,
  включая `group`); ничего не сохраняет;
- `POST {sn, action: "fetch"}` — запрос оригинальному серверу с запомненными заголовками и query
  этой колонки; тело ответа возвращается, ничего не сохраняет; заголовков нет → 409.
- `POST {sn, action: "push"}` — принудительный перезапрос конфига: Push `push_update_config`
  в живую WS-сессию устройства (колонка сама сделает `get_sync_info`); нет живой сессии →
  409 `push_no_session`.

### Замены в ответе «Напрямую»

Своё у каждого устройства: `state.quasar_direct_replace = [{enabled, pattern, replace}, …]`, порядок
важен (редактор — кнопка «Замены в тексте» в панели «Напрямую»). `PUT {sn, replace}` проверяет каждый
`pattern` через `re.compile` (и шаблон `replace` — ссылки на группы); ошибка → 400 с текстом
`Строка N: <ошибка re>`, ничего не сохраняется. Пустой `pattern`, больше 50 правил, `pattern`/`replace`
длиннее 2000 символов — тоже 400. Пустой список удаляет поле.

Применение (`quasar_replace.py`, из `Dispatcher.direct_sync_info`): только при статусе 200 и только
включённые правила, по порядку. Тело распаковывается как в `decoded_json` (gzip/deflate), берётся
текст UTF-8, к нему по очереди `re.sub(pattern, replace, text)` (синтаксис Python `re`: `\1`,
`\g<name>`). Если текст изменился, колонке уходит несжатое тело без `Content-Encoding` и с верным
`Content-Length`; не изменился — оригинал байт-в-байт. Защита: исходное тело было JSON-объектом, а
после замен перестало им быть (или regex упал во время работы) → колонке уходит **исходный** ответ,
в `runtime.recent` пишется `{kind: quasar_replace, error}` с номером последнего применённого правила.

`state.quasar_direct_last.body` остаётся ответом Яндекса; если замены что-то изменили, добавляются
`body_sent` (JSON после замен) и `replaced` (число сработавших правил). Журнал трафика пишет ответ
Яндекса (то, что получил эмулятор): разделения «оригинал/отправлено» у записи журнала нет.
Тесты: `tests/test_quasar_direct_replace.py`.

#### «И в прозрачном маршруте»

`state.quasar_direct_transparent: bool` (своё у каждого устройства, по умолчанию `false`, `false`
хранится отсутствием поля). Включена → при маршруте устройства «Прозрачно» (`proxy`) ответ
`get_sync_info` обрабатывается так же, как в «Напрямую» (`Dispatcher.direct_sync_info`: пересылка,
замены, защита JSON, `quasar_direct_last`, журнал по опции «Запись», ошибка пересылки — 502).
Условия — все сразу: источник устройства `direct`, галочка включена, хост (после алиасов)
`quasar.yandex.net`, путь `/get_sync_info`, устройство опознано. Иначе, как и весь остальной
трафик маршрута, запрос идёт прямым проходом байт-в-байт; WS не затрагивается. В «Эмуляции» и
«Вместе» галочка ни на что не влияет: замены «Напрямую» там работают как обычно.

Заголовки последнего `get_sync_info` каждого устройства (включая `Authorization`) запоминаются
**только в памяти** `runtime` (по SN), в любом режиме опроса; на диск и в state не пишутся. При
маршруте устройства «Прозрачно» запросы идут в Яндекс напрямую: источники
«Генерируемый» и «Свой» не применяются, «Напрямую» — только с галочкой «И в прозрачном маршруте»
(см. выше). Тесты: `tests/test_quasar_source.py`.
