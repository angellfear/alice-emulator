# Настройки эмулятора

Модули: `settings_service.py` (жизненный цикл), `settings_models.py` (pydantic-модели),
`ui/api/settings.py` (API панели). Хранение — `state/emulator.sqlite3` ([state-store](state-store.md)):
настройки целиком в ревизиях БД, тела сценариев — в файлах `state/scenarios/` (файлы — источник
правды, ревизия хранит заглушки `{id, enabled}`). MCP-серверы — отдельно в `state/mcp.json`
([mcp](mcp.md)), каталог параметров — [params-db](params-db.md).

## Формы и API

- `GET /emulator/api/settings` → `Runtime.public()`: копия настроек с масками секретов и
  служебным полем `_rev` (время последнего сохранения).
- `PUT` (полная форма или точечные вкладки) → `SettingsService.validate(value, current)` →
  `Runtime.save_settings`: замок, `persist` (ревизия + сверка файлов сценариев), прогревы.
  Устаревшая копия формы (чужой `_rev`) — 409; ошибка значения — 4xx с именем поля.
- Прямое чтение `runtime.settings[...]` — текущий способ доступа подсистем; значения по
  умолчанию и проверка форм — в моделях (`settings_models.py`).

## Модели (pydantic v2)

- Разделы — `BaseModel` с `extra="forbid"`: неизвестный ключ или неверный тип →
  `ValueError «раздел.поле: …»` → 4xx. Умолчания модели совпадают с `DEFAULT`.
- Исключение — секции источников `model`/`stt`/`tts` (`extra="allow"`): пресеты
  voice_stack пишут туда конфигурацию адаптера — `adapter` и его поля, набор
  объявляет пакет/расширение (`voice_stack/packages/*.json`); это текущая
  функциональность, а не переходное разрешение.
- Секреты (`model`/`stt`/`tts`/`memory.embed` — `api_key`, `agent` — `webhook_token`,
  `self_update` — `token`) — `SecretStr`: не попадают в repr/логи и текст ошибки
  валидации; в настройки и БД возвращается реальное значение (`checked_section`
  раскрывает). Наружу — `public()`: непустое значение → `__KEEP__`, пустое → `""`,
  ссылка `env:ИМЯ` — как есть (значение живёт в окружении процесса). Форма возвращает
  `__KEEP__` — сервер восстанавливает прежнее значение.
- Не `pydantic-settings`: источник настроек — БД, а не переменные окружения.

## Загрузка и сохранение

- `load()`: настройки из БД или `DEFAULT`; досев отсутствующих ключей значениями по
  умолчанию (сохраняется ревизией); дозаполнение новых стандартных ответов по id
  (пользовательские тексты не трогаются); файлы сценариев — источник правды.
- `validate()`: модели разделов; `intelligence` — уровень или режим расширения
  (`ext:<id>`); `standard_replies` — межзаписные правила (`behavior.validate_standard`);
  свободные формы `tools`/`device_context`; восстановление `__KEEP__`.
- `persist()`: ревизия (`revision` — заглушки сценариев) + сверка каталога
  `state/scenarios/` с настройками.

Снимок `public()` на обезличенной базе — `tests/fixtures/settings/`,
`tests/test_settings_snapshot.py`: JSON до и после правок моделей совпадает побайтно.
Старых форматов и переходных слоёв нет («Легаси нет»): перенос живого state выполнен,
миграции удалены.
