# Каталог приложений

Код: `server_emulator/catalog.py`.

## Обзор

Ответ на `/gproxy/get_app_catalog`: режимы и разделы.

## Режимы и разделы

`/gproxy/get_app_catalog` перехватывается при любом маршруте устройства (в «Прозрачно» — как OTA,
`dispatcher.app_catalog_response`). Режим в `catalog.json` (`mode`, миграция с выключателя
`enabled`): `direct` — каталог Яндекса без изменений; `merged` — каталог Яндекса и свои
приложения; `own` — только свои. База direct/merged — живой ответ Яндекса через мост upstream
(петлю закрывает резолвер внешнего DNS) с кешем последнего удачного ответа
(`data/catalog/upstream.bin`, показывается во вкладке «Каталог приложений» → «Каталог Яндекса»);
нет облака и кеша — merged отдаёт только свои, direct — 502. Запись приложения: поле 8 (varint) —
versionCode, по нему колонка решает «Обновить» (раньше версия записывалась в чужое поле —
«Обновить» висел постоянно). Свои разделы — `sections` в catalog.json (порядок, переименование,
удаление: приложения переходят в «Другое»); в merged своё приложение попадает в группу Яндекса по
заголовку раздела, свой раздел — новая группа без enum-категории (колонка группирует по enum,
новые значения не изобретаются); в own — только свои разделы и «Другое».
