# Поставщики данных: виды, реестр, выбор, API

Код: общий реестр видов `server_emulator/providers.py`, API-домен
`server_emulator/ui/api/providers.py`, вкладка `server_emulator/ui/providers.js`.
Тесты: `tests/test_providers.py` (домен), `tests/test_builtin_plugins.py`
(встроенные), `tests/test_music_provider.py` / `tests/test_music_spotify.py` /
`tests/test_music_yandex.py` (поставщики музыки).

## Виды поставщиков

Поставщик данных — точка подключения плагина, откуда сценарии берут содержимое.
**Вид** — строка объявления плагина (`contributes.providers[].kind`): таблицы видов в
ядре нет, новый вид появляется объявлением. Модуль поставщика обязан объявить
`PROVIDER` с непустым `id`; требования к функциям вида объявляет **потребитель** —
`providers.require(kind, обязательные, опциональные)` при импорте:

| Вид | Потребитель → функции | Кто читает | Состояние |
|---|---|---|---|
| `music` | `music.py` → `search(ctx, query, kind)`, `neighbor(ctx, track_id, context, step)`; опционально `rate(ctx, track_id, like)`, `commit(ctx, track_id)`, `queue(ctx)` (окно очереди для виджета) | сценарий `media.music`, ядро `music.py` | работает |
| `weather` | `scenario_plugins.py` → `forecast(ctx, location)` — прогноз в форме Open-Meteo (`current`/`hourly`/`daily`), `location` — `{"latitude", "longitude", "timezone"?}` из параметров дома | сценарий `informers.weather`, виджет погоды | работает |
| `news` | `scenarios/informers/news.py` → `headlines(ctx, kind)` → `{"items": ["заголовок", …], "note"?}` | сценарий `informers.news` | работает (встроенный — заглушка без сети) |
| `video` | `scenarios/media/video.py` → `catalog(ctx)` → `{"items": [запись каталога, …], "note"?}`; запись: `title`, `embed`; необязательные `url`, `genre`, `host`, `player`, `duration`, `year`, `preview` — host/player без значения сценарий выводит из адреса `embed`; необязательная `search(ctx, query)` — поиск самого поставщика, его выдача не фильтруется | сценарий `media.video` | работает (встроенные — каталог ссылок и YouTube) |

Поставщик без обязательной функции вида в реестр не попадает — расширение
отключается целиком, причина видна в карточке расширения; вид без потребителя
регистрируется без проверки функций, их проверит потребитель, когда появится.
Модуль без `PROVIDER` — вспомогательный и не участвует. Первый аргумент функций
вида — ExtensionContext плагина (настройки свежие); встроенная заглушка тестов с
несуществующим плагином получает пустые настройки. Потребитель вида может объявить
свой вызов — `providers.call_invoker(kind, invoker)` при импорте: `providers.invoke`
и ступень свободных хвостов («включи {X}» без слова «музыку» — `scenario_engine/dialog.py`,
`_search_stage`) зовут им; музыка (`music.invoke`) передаёт SDK-контекст вызова
первым аргументом и OAuth-токен аккаунта Яндекса в `ctx.extension` с обменом по
`token_expired` — тот же вызов, что у сценария. Без объявления функции получают
ExtensionContext. Интерфейс поставщика музыки —
[player.md](player.md), раздел «Поставщик контента».

## Погода: датасет как кеш, диспетчер

Сценарий погоды спрашивает запись датасета `weather` (`ctx.dataset_record`); обновляет
её диспетчер `scenario_plugins.weather_plugin(runtime)` вызовом `forecast` выбранного
поставщика (args — координаты дома из параметров пользователя). Свежая запись — сразу,
устаревшая — вызов поставщика с таймаутом (`server.weather.refresh_timeout`), при сбое —
старая запись с пометкой «Данные не актуальны» или честный отказ. Поставщика нет —
сценарий отвечает «Для этого нет источника данных.», а его фраз нет в справочнике:
фразы («какая погода», «сколько градусов») объявляет плагин погоды
(`phrases/weather.json`, handler `core:informers.weather`). Встроенный
`builtin.open-meteo` включён по умолчанию, URL его API — настройка плагина
(Open-Meteo-совместимый), резерв при недоступности — api.met.no.

## Новости

Сценарий `informers.news` («новости», «что нового», «расскажи новости») произносит
заголовки выбранного поставщика репликой: директив/карточки нет — образца ответа
настоящего сервера на «новости» в журнале нет (по записи карточка добавится по
образцу). Фразы сценария живут не в нём, а в справочнике плагина
(`phrases/news.json`, запись `news` с handler `core:informers.news`): без плагина
фраз нет. Встроенный `builtin.news-stub` — заглушка без сети: фиксированные
заголовки объявлены в самом плагине. Кеша/очереди у ядра нет — частоту обновления
ведёт сам поставщик; `note` пустой ленты произносится как честный отказ.

## Видео

Сценарий `media.video` показывает выдачу каталога поставщика вида video («открой
список комедий») и запускает выбранную по номеру запись («один», «номер два»).
Ответ собран по образцу журнала: `open_search` с веб-карточками SearchVideoItem —
у каждой два одинаковых voice-control с сущностью `selected_video_title` (фразы
«название / N / номер N»), второй директивой `tts_play_placeholder`; запуск —
`play_web_video_directive` + «Запускаю.» (AnalyticsType — название видео). VideoId,
ReqId и Doc2docUrl внешнего поиска в карточки не попадают. Фильтр выдачи — по
последнему слову запроса (нормальная форма слова): совпадение с жанром или словом
названия; общие слова («фильм», «кино», «видео», «ролик», «медиа», «подборка»)
показывают весь каталог; совпадений меньше трёх — честный отказ (выдача рассчитана на выбор по
номеру). Список запоминается в данных сценария до новой выдачи; «ещё»/«назад» листает
сама колонка (`device.screen.navigation`), о закрытии экрана эмулятору не сообщают.
Фразы — в справочнике плагина (`phrases/video.json`): поиска («открой список
{query}», «список {query}») и выбора («[номер ]{num}»). Встроенный
`builtin.video-links` — каталог ссылок, правится в настройках плагина (JSON-список),
сети нет — ссылки открывает плеер колонки. Встроенный `builtin.youtube` — поиск YouTube
(`search` через yt-dlp, без ключа API; «найди на ютубе {query}»). Касание карточки
выдачи приходит фреймом `gallery_video_select_semantic_frame` (`embed_uri`, `url`,
`title`; маршрут колбэка `video.selected`) — запуск тем же ответом, что выбор номером. Без образца в журнале не реализовано:
карточка фильма (`centaur_open_video_details_screen`), `video_play` поставщиков,
экран поиска divui, внешний поиск.

## Реестр

Реестр пересобирает `runtime.rebuild_extension_registries` из объявлений
`contributes.providers` включённых плагинов: точку подключения (модуль) называет сам
плагин, папка вида точкой подключения не является (детали —
[extensions.md](extensions.md)). Встроенный (`origin: builtin`) и внешний
(`origin: extension`) живут рядом, их разводит приставка `builtin.` в id.
Конфликт одинаковых id **в пределах вида** или битый модуль отключает расширение
целиком (как у actions/datasets). Вид, объявленный плагином впервые, регистрируется
без проверки функций — их проверит его потребитель, когда появится; если потребитель
импортируется позже сборки, `providers.require` дообогащает уже собранные записи.
Название вида для вкладки — из объявления (`providers.kind_title`), возможности
(`capabilities`) — тоже из объявления (в записи реестра).

## Встроенные плагины

Минимальный набор поставляется с эмулятором (`server_emulator/plugins/`):
музыка — `builtin.spotify` и `builtin.yandex-music`, погода — `builtin.open-meteo` и `builtin.yandex-weather` (API Яндекс Погоды v2, ключ в настройках),
новости — `builtin.news-stub`, видео — `builtin.video-links` и `builtin.youtube`. Установлены всегда, версия = версия эмулятора,
включены по умолчанию; включение/выключение и настройки — как у внешних; удалить/
обновить/откатить и установить чужое с id `builtin.*` нельзя (details —
[extensions.md](extensions.md), раздел «Встроенные плагины»).

## Выбор поставщика

Выбранный поставщик вида — `settings["providers"][<вид>] = id`; пусто — авто (первый
включённый по алфавиту), поставщиков нет — None (сценарий отвечает честным отказом).
Сценарий-потребитель берёт поставщика через `ctx.provider(<вид>)` (SDK 2.6.0): владелец
совпавшей записи справочника, иначе выбранный; музыка — `ctx.music`.

Признак сервиса вместо id: `PROVIDER["service"]` (`"yandex-music"`) — захваченный
OAuth-токен и ключ меты протокола определяются сервисом, а не id поставщика
(встроенный `builtin.yandex-music` и внешний `yandex-music` — два поставщика с одним
сервисом, токен получают оба); без `service` — совместимость с уже установленным
внешним по id.

## Очередь поставщика и перезапуск

Своей очереди ядро не хранит — очередь ведёт поставщик. Поставщик сохраняет её в
SDK-хранилище сценария (`ctx.data`, ключ с его id — `music_queue/<id>`) и
гидратирует при первом обращении после перезапуска сервера: «Плей» с виджета
продолжает последний трек, «Далее/Назад» идут от него без новой голосовой команды.
В хранилище — идентификаторы очереди и позиция (и атрибуты треков для виджета);
ссылки потоков — только вместе со временем получения, при чтении отбрасываются по
TTL (подписанные URL живут ограниченное время): свежая ссылка после рестарта
работает сразу, протухшая добирается заново один раз. Секретов и токенов в
хранилище нет. Очередь — первые 30 треков списка поставщика в его порядке (в хранилище
остаются и треки без ссылки потока: ссылки добираются лениво). У Яндекс.Музыки для мгновенного отклика кнопок — ещё и кеш ссылки
потока с TTL и предзагрузка соседей внутри поставщика; из кеша кнопка отвечает
без обращений к API. У встроенных поставщиков это `builtin.spotify` и
`builtin.yandex-music` (`music_queue/spotify`, `music_queue/yandex-music`).

## Плейлист по умолчанию

«Включи музыку» без запроса запускает плейлист по умолчанию — настройка поставщика
`default_playlist` (вкладка «Расширения» / «Поставщики данных → Музыка»).
Яндекс.Музыка: «Мне нравится» (по умолчанию; новые лайки первыми), «Моя волна»
(станция `user:onyourwave`, первая порция) или название плейлиста пользователя; названного
нет или он пуст — «Мне нравится», затем волна; ничего нет — вопрос «Что включить?» со
слушанием ответа. Spotify: ссылка или id публичного плейлиста (нужны ключи Web API);
не задан — случайный трек из кеша прошлых поисков, затем вопрос. Любимые треки аккаунта
Spotify не используются (пользовательский токен поставщику не передаётся).

## Вход аккаунта поставщика

Плагин-поставщик может объявить три функции входа аккаунта — `login_start(ctx, redirect_uri)`,
`login_callback(ctx, params)`, `login_status(ctx, tokens)` (все async; наличие всех трёх в
модуле включает точку: запись реестра получает `login`, кнопка «Войти в <название>» в
вкладке появляется только у объявивших). Смысл — получить токены аккаунта пользователя без
ручного копирования: у Spotify это Authorization Code + PKCE через `authlib` (зависимость
ядра, `authlib>=1.3,<2`), у других поставщиков — их протоколы.

- `login_start` строит URL страницы входа; redirect задаёт вызывающий — loopback
  `http://127.0.0.1:<порт>/emulator/api/providers_login_callback` из Host запроса (Spotify
  разрешает любой порт для loopback-литерала `http://127.0.0.1`, в Dashboard он
  регистрируется без порта; кнопка работает при входе в панель по `http://127.0.0.1:<порт>`).
- `login_callback` получает query-параметры redirect (code/state или error), меняет код на
  токены и возвращает их вызывающему для сохранения; authlib проверяет state против
  authorization_response. Токены не попадают в браузер, журнал и ответы API.
- `login_status` принимает сохранённые токены и отвечает `authorized` (у Spotify — с
  автообновлением истёкшего access через refresh_token; свежий набор возвращается в
  `tokens` для перезаписи).

Хранение токенов — `state/`: meta `provider_login:<ext_id>` (JSON access/refresh/expires_at),
запись и чтение — API-домен, плагин получает их аргументом. Наружу только статусы: GET
`providers` — флаг `login` и `status.login_authorized` у поставщика. API входа:
`POST /emulator/api/providers_login {kind, id, action: "start"|"status"}` (`start` → `{url}`;
`status` → `{authorized, expires_in?}`) и `GET /emulator/api/providers_login_callback?…` —
цель redirect (браузер после страницы входа, без заголовка X-Emulator; отвечает
страницей-статусом). Тесты — `tests/test_provider_login.py` (подделка токен-эндпойнта).

## API

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/emulator/api/providers` | `{kinds: {<вид>: {title, selected, providers: [{id, title, extension, origin, enabled, login, status}]}}}` — только виды, у которых есть поставщики; `origin` — `builtin` или `extension`; `login` — у поставщика есть точки входа (кнопка в UI); `status` — у Яндекс.Музыки `oauth_captured`, у поставщиков с входом `login_authorized` (сам токен не выводится) |
| PUT | `/emulator/api/providers` | `{kind, id}` — выбор активного; `id: ""` — авто. Сохраняется только ключ `settings["providers"][kind]` (как у intelligence); неизвестный вид или выключенный/неизвестный id — 400 |
| POST | `/emulator/api/providers_login` | `{kind, id, action}` — `start` → `{url}` страницы входа (redirect — loopback из Host; поставщик без client_id — 502 с текстом), `status` → `{authorized, expires_in?}`; поставщик без точек login — 400 |
| GET | `/emulator/api/providers_login_callback?…` | цель redirect входа (браузер после страницы входа, без X-Emulator): обмен кода на токены (в meta state/) и страница-статус; неизвестный state или отказ сервиса — страница ошибки |

## UI

Группа «Поставщики данных» и её вкладки строятся из ответа GET (`app.js` по образцу
режимов расширений): нет видов — нет вкладки, нет поставщиков вообще — группы нет.
Одна вкладка-шаблон на любой вид (`providers.js`): секция `#providers-<вид>`
создаётся динамически. Радио-список «Авто — первый включённый» + поставщики
(встроенные — с пометкой; Яндекс Музыка — статус захвата токена аккаунта; поставщики
с точками login — кнопка «Войти в <название>» со статусом «вход выполнен / ещё не
выполнен», клик ведёт на страницу входа сервиса; одно пояснение на раздел — условия
Dashboard сервиса и требование входа в панель по `http://127.0.0.1:<порт>`). Настройки
выбранного поставщика — готовая форма вкладки «Расширений»
(`window.extensionSettingsBlock`), сохранение — `POST api/extensions {op: "set"}`.

## Не реализовано

- Статусы других поставщиков (кроме захвата токена Яндекс.Музыки и статуса входа Spotify).
- Тематические ленты новостей (`kind` запроса пока общий, «top»).
- Карточка новостей — по образцу настоящего сервера, когда появится запись в журнале.
- Возможности поставщика (`capabilities` объявления): у музыки — `fairy_tales`,
  `podcasts`, `audiobooks`, `catalog_search`. Фразы сказок, подкастов и аудиокниг
  есть, только если у выбранного поставщика есть такая возможность.
- Погода и новости активны, только когда есть включённый поставщик вида. Сейчас без
  поставщика они отвечают честным отказом.
- Вид `video`: ветка с карточкой фильма (`centaur_open_video_details_screen`),
  `video_play` поставщиков и экран поиска divui — по образцам журнала, когда
  появятся записи. Каталог и выдача по номеру — работают (раздел «Видео»).
- Классы сценариев и перенос фраз контента в плагины —
  [scenarios.md](scenarios.md), разделы 2 и 10.
