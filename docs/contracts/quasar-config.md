# Quasar-конфиг: платформенные базовые конфиги + переопределения устройств

## Архитектура

### 1. Файл платформы — `state/quasar/platforms/<platform>.json`

Один файл описывает и базовое тело, и редактор. Два корневых ключа:

```json
{
  "platform": "chiron",
  "title": "Станция с экраном (chiron)",
  "description": "Базовый ответ /get_sync_info для платформы chiron",
  "sync": { "...": "полное базовое тело ответа: config/tags/glagol/subscription/…" },
  "controls": [
    {
      "path": "subscription.enabled",
      "type": "select",
      "label": "Подписка",
      "hint": "Состояние подписки Алисы для устройств платформы",
      "options": [
        {"value": true, "label": "Включена",
         "patch": {"subscription": {"enabled": true, "disabled_reason": null}}},
        {"value": false, "label": "Выключена (invalid_subscription_user)",
         "patch": {"subscription": {"enabled": false, "disabled_reason": "invalid_subscription_user"}}}
      ]
    },
    {"path": "tags", "type": "text-list", "label": "Теги", "hint": "…"},
    {"path": "config.device_config.name", "type": "text", "label": "Имя устройства",
     "value_hint": "подставляется имя из реестра, если не задано явно"}
  ]
}
```

Ключевые решения:

- **`options[].patch` — поддерево, а не скаляр**: вариант селектора меняет столько
  полей, сколько нужно (пара enabled + disabled_reason меняется вместе). Это
  обобщение примера пользователя «селектор подставляет нужное значение в тело».
- **Типы контролов**: `select` (варианты с patch), `toggle` (сахар: select из двух
  вариантов вкл/выкл), `text`, `number`, `text-list`, `code` (см. «Источники
  значений»), `db`. Набор расширяемый — контрол описан данными, UI рендерит по `type`.
- **`path`** — точечный путь в `sync`; текущее значение контрола в простом виде
  читается из базового тела (нет отдельного хранилища «значений контролов» —
  тело и есть состояние, контролы — только правила отображения/правки).

### 2. Источники значений (динамика) — один движок

Переиспользуем плейсхолдеры каталога эндпоинтов (`endpoints.TOKENS`), никакого
второго синтаксиса. Везде, где ожидается значение (лист `sync`, patch, override),
допустима строка с токенами + три специальных источника (решения по ответам):

- `{"expr": "{{now_iso}}"}` — шаблон на момент запроса. Контекст: запросные
  `now/now_ms/now_iso/uuid` (из endpoints) + токены реестра эмулятора:
  `{{device_id}}`, `{{device_name}}`, `{{platform}}`, `{{user_id}}`,
  `{{user.name}}`, `{{user.location.city}}`, `{{device.room}}`,
  `{{device.fields.<ключ>}}`, `{{user.fields.<ключ>}}`;
- `{"db": "<точечный путь>"}` — **значение из БД эмулятора** (реестр): корни
  `user.` (name/location/fields) и `device.` (name/room/fields/state). Даёт
  целые объекты/массивы (когда токен-строка неудобна);
- `{"run": "<команда>"}` — **запуск внешнего скрипта/exe сервером** (не eval):
  subprocess из белого списка `state/quasar/scripts`, таймаут ~3 с; stdout → значение (если парсится как JSON —
  структура, иначе строка с тримом); переменные окружения QSN/QDEVICE_ID/
  QUSER_ID/QPATH/QCONTEXT(json) передают контекст; ошибка/таймаут — значение
  базового тела остаётся, инцидент пишется в runtime.recent. В UI — поле
  команды с подсказкой формата.

### 3. Переопределения устройств

Хранятся в реестре устройства: `device.state.quasar_overrides` —
`[{"path": "config.device_config.name", "source": {...}, "notes": ""}]`, где
`source` — либо `{"option": "<id варианта из контрола платформы>"}`, либо явное
значение/`expr`/`run`/`db` (как выше). Переживает рестарты, виден в существующем
API identities.

Композиция ответа `/get_sync_info` (quasar.py):

```
base(платформа устройства)  →  применить overrides по path (deep-set)  →  рендер
динамических источников  →  {status: ok, **результат}
```

Платформа устройства берётся из `device.profile.platform`, при отсутствии —
`default` платформа (файл с флагом `"default": true`; fallback — первый файл).

### 4. API (admin, `/emulator/api/…`)

- `quasar_platforms`: GET — общий common (тело) со счётчиками (`common_keys`,
  `common_inline`), `builtin_platforms` и `builtin_counts` (имена и числа
  ключей платформ встроенной базы из `quasar_defaults/platforms/`) и список
  платформ-патчей с метаданными (платформа, default, `keys`, patch_bytes);
  GET `?platform=` — файл целиком;
  GET `?builtin=<платформа>` — встроенная база (`generated_base`: `{config,
  keys}`; имя вне белого списка — общий дефолт); GET `?compose=<платформа>` —
  итог слоёв без устройства (база → common → патч) с `origins`: инлайн-узлы
  разрешены по выбранным вариантам, `{{токены}}` и source-маркеры (expr/db/run)
  остаются как есть; PUT — сохранить common (`common_file`) или патч платформы
  (`platform_file`); DELETE `?platform=`.
- Переопределения — через существующий `identities` (state), UI пишет
  `quasar_overrides` в состояние устройства.

### 5. UI (вкладка «HTTP · Quasar» → «Quasar»)

```
┌──────────────┬───────────────────────────────────────────────────────┐
│ Встроенная   │ заголовок слоя · select платформы · ⋯ · «Итог для X»  │
│ база         │ Настройки: инлайн-узлы строками                       │
│ Общий  ◀     │ JSON слоя: поиск по путям + дерево | редактор ветви   │
│ Платформа    │ (редактор справа при панели ≥ 760 px, иначе ниже)     │
│ Под          │ полоса: N изменений · Отменить · Сохранить            │
│ устройство   │                                                       │
└──────────────┴───────────────────────────────────────────────────────┘
```

- **Стек слоёв** слева, панель активного слоя справа (узкий экран — компактный
  сегмент из коротких подписей над панелью, страница без горизонтальной
  прокрутки на 400 px). Слои в порядке сборки: «Встроенная база» — только
  чтение, свой выбор платформы, число ключей; «Общий» — пользовательский
  common, ключи и настройки; «Платформа» — select платформ-патчей + меню «⋯»
  (добавить / переименовать / удалить — через `<dialog>`); «Под устройство» —
  раздел переопределений в той же панели (список устройств — модуль
  `devices_common.js`: modelBySn/картинка/статус/IP; справа список
  override'ов, «＋ добавить», редактор источника по типу).
- **Панель слоя**: настройки по инлайн-узлам ($bool — переключатель, $select —
  список, $string/$number/$list — поля, $param — диалог выбора ключа), «JSON
  слоя» — свёрнутый блок с поиском по путям, деревом и редактором ветви
  (CodeMirror; редактор справа от дерева при ширине панели ≥ 760 px —
  container query, иначе под деревом; у базы — read-only и без настроек);
  изменения копятся в локальном теле и сохраняются полосой внизу (sticky),
  переключение слоя/платформы при несохранённом — диалог «Сохранить / Не
  сохранять / Отмена». «Итог для <платформа>» — диалог с собранным конфигом
  без устройства, read-only CodeMirror и тултипом происхождения значений.

### 6. Миграция живых данных

- Из текущих `state.quasar` устройств (залитые capture-конфиги): платформа
  устройства определяется по заголовкам из дампов/`profile.platform`; для каждой
  платформы первый (эталонный) device-конфиг становится базой файла платформы;
  расхождения конфигов других устройств
  той же платформы (имена, сертификаты, ids) — их overrides.
- Старое поле `state.quasar` после перехода не читается (композиция новая);
  хранится как backup-ключ `quasar_legacy` один релиз.

## Редактор и происхождение значений

- «JSON слоя»: граф-дерево со сворачиванием +/- (глубина ≥2 свёрнута по
  умолчанию, состояние запоминается; поиск по путям показывает совпавшие
  ветви с предками раскрытыми); инлайн-узлы в дереве НЕ раскрываются —
  строка с кнопкой «Шаблон», целиком открывается в редакторе.
- Редактор кода и просмотрщик — готовая библиотека CodeMirror 5
  (ui/vendor/, раздаётся static как vendor/*): подсветка JSON, номера строк,
  фолдинг (foldgutter+brace-fold), matchbrackets, тема material-darker.
  Чипы-подсказки — свёрнутый блок «Вставки» под редактором. Хлебная крошка
  «Ветвь: <путь>» обновляется при выборе; программная установка значения
  не помечает файл изменённым (нет ложных вопросов о несохранённых
  изменениях); правка применяется кнопкой «Сохранить ветвь» и копится в
  полосе изменений слоя.
- compose(..., trace=None, platform_label=..., render=True) — словарь
  «dotted-путь → подпись происхождения»: «платформа X» (в т.ч. удалённые
  ключи), «переопределение устройства/выбор/БД/скрипт/удаление», «шаблон
  «имя»: вариант «…»», «параметр user.*», «динамика {{токен}}», «БД
  эмулятора: …», «скрипт: …». Без trace — прежнее поведение. render=False —
  сборка без устройства: инлайн-узлы разрешаются по выбранным вариантам,
  строки и source-маркеры остаются как есть (просмотр слоёв).
- count_keys/count_inline — счётчики размера слоя (листовые значения;
  инлайн-узлы) для стека слоёв; trace_layer помечает пути, добавленные или
  изменённые слоем относительно предыдущего.
- API GET /api/quasar_composed?device=SN — итоговый конфиг после всех
  слоёв + origins + список переопределений (legacy-конфиг помечен флагом).
- UI «Итог для <платформа>» и «Переопределение под устройство»: итоговый
  конфиг — read-only CodeMirror; наведение на строку — тултип «путь →
  происхождение» (по карте строк и цепочке ближайшего предка); в
  переопределениях клик по строке — диалог с предзаполненными путём и
  текущим значением.

## Личные данные в шаблонах платформ

Решения по личным данным:
- имя устройства — БАЗА УСТРОЙСТВА: common → device_config.name = $param
  device.name (реестр, вкладка «Устройства»); имена перенесены из облака;
- glagol.security.{server_certificate,server_private_key} — ПЕРСОНАЛЬНЫЕ
  (различаются между устройствами) → база параметров: device.glagol_cert /
  device.glagol_key (scope=device, secret, значения из захватов). Общий узел
  в common ссылается $param; алгоритм генерации сертификатов облаком
  (подпись CA Яндекса) не восстановлен — для новых устройств без захвата;
- теги — в ШАБЛОНЕ ПЛАТФОРМЫ ($list в chiron.json / yandexstation_2.json),
  персональные отличия (C00JN, C00NX) — override устройства;
- env/appmetrikaReportEnvironment/quasmodrom_subgroup — common = большинство
  Дуо, отличия устройств (C00ZT release_control, Макс production) — override;
- максовские персональные ключи device_config (equalizer/calls_settings/
  allow_non_self_calls/hdmiAudio/led/standby/location) — патч yandexstation_2
  (+ null-удаление intonationSpotting/palm_gesture, которых у Макса нет);
- C00JN — персональные настройки (equalizer lessbass, dndMode с расписанием,
  calls_settings, radio_nanny, intonation ms) — overrides устройства;
- wifi-хеш: структура облака {"wifi_hash": <хеш>} — $param вложен в лист,
  мета-ключи $name/$hint допустимы ТОЛЬКО внутри инлайн-узлов (иначе попадают
  в ответ станции).

Резервные копии шаблонов — *.json.bak рядом с файлами.

## Слой аккаунта

Основание — разбор источников ответа: на настоящем сервере `config` собирается из частей
с разными владельцами — `account_config` (аккаунт, меняется из приложения), `device_config`
(устройство), `system_config` (сервер, снаружи не пишется). Эмулятор повторяет это владение слоем
переопределений владельца.

### Порядок слоёв `/get_sync_info`

```
built-in generated (quasar_defaults/common.json + платформенный квирк)
  → common (state/quasar/common.json) → merge-patch платформы
  → переопределения аккаунта → переопределения устройства
  → инлайн-узлы ($select/$string/…) → динамика ({{токены}} / db / run)
```

Устройство сильнее аккаунта: одно и то же значение, заданное в обоих слоях, берётся из
переопределения устройства. Платформа слабее аккаунта: аккаунт всегда поверх патча платформы.
Инлайн-узел ($-ключ типа) в верхнем слое заменяет значение нижнего слоя целиком — узел
описывает значение, а не дополняет его (`merge_layer`).

### Встроенный источник generated

Решение владельца: конфиг генерируется целиком — встроенные дефолты `server_emulator/quasar_defaults/`
— база для всех колонок, а не только замена 409 без слоёв (режимы «Напрямую» и custom —
индивидуальный конфиг — остаются без изменений). Дефолты — полный ответ без захвата,
перенесённый из исходников quasar-server (MIT; commit и пересборка —
`tools/build_quasar_defaults.py` и README рядом с файлами):

- `common.json` — config (account_config/device_config/system_config) +
  `alice_pro_subscription {enabled: true, ttl: 31536000}` + `subscription {mode: "transaction"}`
  + `tags: []`. Персональных значений нет: `device_config.name` — токен `{{device.name}}`,
  остальное заполняет динамика compose;
- `platforms/<платформа>.json` — merge-patch поверх common.json для 13 платформ;
  chiron/magritte — квирк `hybrid_request_factory`: `supported_frames` — объект (у остальных
  массив) и удаление `hybrid_voice_inputs`, остальные файлы — заготовки `{}`.

Платформа базы (квирка и патчей) — одна функция `device_platform`: `device.profile.platform`
→ платформа, которую колонка сама сообщила при опросе конфига (query `platform` в
`/get_sync_info`, запоминается в `state.reported_platform` как «последнее» значение — его же
видят generate и просмотрщик composed, где запроса колонки нет) → пусто: общий дефолт,
первым файлом платформ не угадываем. Пользовательский common перекрывает built-in дефолт,
платформа — common. Карточка источника в UI показывает «Генерируемый (встроенный)», пока
база — только встроенные дефолты.

### Хранение и формат

- У пользователя реестра (`identities`) — список `quasar_overrides` того же формата, что у
  устройства: `[{"path": "...", "source": ...}]`; `source` — литерал / `{"expr"}` / `{"db"}` /
  `{"run"}` / `{"delete": true}` / `{"$select": "вариант"}`.
- **Путь хранится полным**, от корня ответа: `config.account_config.spotter`.
  Полный путь совпадает с путями устройства и ключами `trace`; UI показывает и принимает путь
  внутри `account_config` и добавляет префикс сам.
- Допустимы только пути глубже `config.account_config` (сам узел целиком не заменяется). Путь вне
  этой части — `QuasarConfigError` (в `compose`) / `ValueError` при сохранении (HTTP 400).
- Физически — запись meta `identity_user_quasar` хранилища (`{user_id: [...]}`), как у групп
  стереопар: схема таблицы `users` не менялась. В представлении реестра (`GET identities`) —
  поле `quasar_overrides` пользователя (ключа нет, если список пуст). Правка имени пользователя
  слой не трогает; удаление пользователя удаляет и слой.
- У устройства без владельца слоя аккаунта нет (`/get_sync_info` такому устройству и так отвечает
  403 `device_not_assigned`; в просмотре итогового конфига слой не применяется).

### API

- Чтение — `GET /emulator/api/identities` (`users[].quasar_overrides`).
- Запись — `POST /emulator/api/identities` `{"operation": "user_quasar_overrides", "id": "<user>",
  "quasar_overrides": [{path, source}, …]}`; список заменяется целиком, пустой — очищает слой.
- `GET /emulator/api/quasar_composed?device=SN` учитывает слой аккаунта; в `origins` значения
  подписаны «аккаунт <имя пользователя>» (для `delete`/`$select`/`expr`/`db`/`run` — «аккаунт <имя>
  (<вид>)»); если значение затем перекрыто устройством — «переопределение устройства».

### UI

Карточка пользователя («Пользователи → Параметры»), вкладка «Настройки аккаунта»: список
переопределений, диалог добавления/правки (источник — те же виды, что у устройства), сохраняется
общей кнопкой «Сохранить» диалога.

### `account_config` в патчах платформ

Решение: оставить. Блок `account_config` в `platforms/*.json` (например,
`chiron.json: account_config.informers_enabled`) — значения по умолчанию для платформы; запрета нет.
Аккаунт их переопределяет, устройство переопределяет аккаунт.


## Источник конфига устройства

Каждое устройство выбирает, откуда брать ответ на `GET /get_sync_info`. Режим хранится в
`state.quasar_source` устройства, свой ответ — в `state.quasar_custom`, последний ответ Яндекса —
в `state.quasar_direct_last` (`{ts, status, body}`, тело — распакованный JSON). Отсутствие поля —
режим `generated`.

| Метка | Режим | Что получает колонка |
|---|---|---|
| **Генерируемый** | `generated` (по умолчанию) | конфиг, собранный `compose` над встроенным generated (см. «Встроенный источник generated»); без пользовательского common база — только встроенные дефолты |
| **Напрямую** | `direct` | ответ настоящего `quasar.yandex.net` без изменений; обмен — в «Журнал» (`source=upstream`) по опции «Запись» устройства; успешный JSON сохраняется в `state.quasar_direct_last` |
| **Свой** | `custom` | `state.quasar_custom` как есть: без слоёв, инлайн-узлов и подстановки стереопары; нет сохранённого или в нём нет `config` → 409 `quasar_custom_not_set` |

Маршрут API (`ui/api/quasar_config_api.py`, домен `quasar_source`):

- `GET ?sn=` → `{mode, builtin_base, direct_last, custom, replace, transparent, can_fetch}`;
  `builtin_base` — база собранного ответа сейчас только встроенные дефолты (нет пользовательского
  common и legacy-конфига); `can_fetch` — запомнены ли
  заголовки последнего опроса этой колонки; `replace` — правила замен «Напрямую» (по умолчанию `[]`);
  `transparent` — галочка «И в прозрачном маршруте» (по умолчанию `false`);
- `PUT {sn, mode?, custom?, replace?, transparent?}` — сохранение режима, своего ответа, замен и/или
  галочки под `runtime.lock` (custom — JSON-объект с объектом `config`, иначе 400; `replace` — см.
  ниже; `transparent` — bool, иначе 400);
- `POST {sn, action: "generate"}` — ответ, который собрал бы `compose` (как отдаётся колонке,
  включая `group`); ничего не сохраняет;
- `POST {sn, action: "fetch"}` — запрос оригинальному серверу с запомненными заголовками и query
  этой колонки; тело ответа возвращается, ничего не сохраняет; заголовков нет → 409.
- `POST {sn, action: "push"}` — принудительный перезапрос конфига: Push `push_update_config`
  в живую WS-сессию устройства (колонка сама сделает `get_sync_info`); нет живой сессии →
  409 `push_no_session`.

### Замены в ответе «Напрямую»

Своё у каждого устройства: `state.quasar_direct_replace = [{enabled, pattern, replace}, …]`, порядок
важен (редактор — кнопка «Замены» в панели «Напрямую»). `PUT {sn, replace}` проверяет каждый
`pattern` через `re.compile` (и шаблон `replace` — ссылки на группы); ошибка → 400 с текстом
`Строка N: <ошибка re>`, ничего не сохраняется. Пустой `pattern`, больше 50 правил, `pattern`/`replace`
длиннее 2000 символов — тоже 400. Пустой список удаляет поле.

Применение (`quasar_replace.py`, из `Dispatcher.direct_sync_info`): только при статусе 200 и только
включённые правила, по порядку. Тело распаковывается как в `decoded_json` (gzip/deflate), берётся
текст UTF-8, к нему по очереди `re.sub(pattern, replace, text)` (синтаксис Python `re`: `\1`,
`\g<name>`). Если текст изменился, колонке уходит несжатое тело без `Content-Encoding` и с верным
`Content-Length`; не изменился — оригинал байт-в-байт. Защита: исходное тело было JSON-объектом, а
после замен перестало им быть (или regex упал во время работы) → колонке уходит **исходный** ответ,
в `runtime.recent` пишется `{kind: quasar_replace, error}` с номером последнего применённого правила.

`state.quasar_direct_last.body` остаётся ответом Яндекса; если замены что-то изменили, добавляются
`body_sent` (JSON после замен) и `replaced` (число сработавших правил). Журнал трафика пишет ответ
Яндекса (то, что получил эмулятор): разделения «оригинал/отправлено» у записи журнала нет.
Тесты: `tests/test_quasar_direct_replace.py`.

#### «И в прозрачном маршруте»

`state.quasar_direct_transparent: bool` (своё у каждого устройства, по умолчанию `false`, `false`
хранится отсутствием поля). Включена → при маршруте устройства «Прозрачно» (`proxy`) ответ
`get_sync_info` обрабатывается так же, как в «Напрямую» (`Dispatcher.direct_sync_info`: пересылка,
замены, защита JSON, `quasar_direct_last`, журнал по опции «Запись», ошибка пересылки — 502).
Условия — все сразу: источник устройства `direct`, галочка включена, хост (после алиасов)
`quasar.yandex.net`, путь `/get_sync_info`, устройство опознано. Иначе, как и весь остальной
трафик маршрута, запрос идёт прямым проходом байт-в-байт; WS не затрагивается. В «Эмуляции» и
«Вместе» галочка ни на что не влияет: замены «Напрямую» там работают как обычно.

Заголовки последнего `get_sync_info` каждого устройства (включая `Authorization`) запоминаются
**только в памяти** `runtime` (по SN), в любом режиме опроса; на диск и в state не пишутся. При
маршруте устройства «Прозрачно» запросы идут в Яндекс напрямую: источники
«Генерируемый» и «Свой» не применяются, «Напрямую» — только с галочкой «И в прозрачном маршруте»
(см. выше). Тесты: `tests/test_quasar_source.py`.
