# Контракт раздела «Анимации»

Проекты анимаций дисплеев колонок: хранение по платформам, разбор и сборка родных форматов (.led, .scled, GIF), редактор с плеером в UI, отправка на колонку. Отдельно живёт каталог GIF-кадров станций (`AnimationStore`, домен `animations`): на нём сценарии LED-эмоций и MCP.

## 1. Платформы и дисплеи

Реестр — `PLATFORM_DISPLAYS` в `animations.py`. Колонка относится к платформе по профилю/модели, иначе по типу-символу SN (`device_platform`). Платформы без дисплея (ДуоМакс) в реестре нет и в разделе не показываются; остальные платформы видны всегда, даже без единой колонки пользователя — редактор, каталог, импорт и экспорт работают независимо от парка устройств, отправка на колонку просто недоступна, пока колонки нет.

| Платформа | Дисплей (`kind`) | Размер | Родной формат | Отправка на колонку |
|---|---|---|---|---|
| yandexstation_2 | `frontal` | 25×16 пикселей, чёрно-белый (пиксель вкл/выкл) | GIF | да |
| yandexstation_2 | `ring` | 24 LED | .led | да |
| yandexmidi | `panel` | 84 LED | .led | нет |
| yandexmidi | `oknix` | 5 LED | .led | нет |
| yandexmini_2 | `ring` | 6 LED | .led | да |
| yandexmini_2 | `clock` | 32 сегмента | .scled | да |
| yandexstation, yandexmini | `ring` | 24 LED | .led | да |

`GET api/animations-platforms` → `{platforms: [{platform, title, displays: [{kind, title, size, format}], devices: [{sn, name, model}]}]}`: все платформы реестра, в его порядке; `devices` — колонки пользователя этой платформы (для списка «Проиграть»), пустой список — колонок нет.

## 2. Проект

Файл `state/animations/<platform>/<id>.json`:

```json
{"platform": "yandexmini_2", "id": "my.clock.1", "title": "Часы 1", "kind": "clock",
 "size": [32], "loop_from": -1, "frames": [{"brightnesses": [0, "… 32 значения"], "delayMs": 100}]}
```

- `id` — `[a-z0-9_.-]{1,64}`; `title` — непустая строка; `kind` — дисплей платформы; `size` берётся из реестра, не от клиента.
- `loop_from` — индекс кадра, с которого анимация зацикливается; `-1` — без цикла. GIF этот
  индекс выразить не умеет: при экспорте и отправке frontal-проекта с циклом GIF повторяется
  целиком (от первого кадра); от `loop_from` играет только предпросмотр в UI. Поле зацикливания
  у `draw_led_screen` в образцах настоящего сервера не встречалось (payload — только
  `animation_sequence` и `till_end_of_speech`), поэтому повтор целиком делает сам GIF (метка
  Netscape loop) при экспорте и отправке. Импорт GIF читает метку цикла источника: зацикленный
  GIF сохраняется с `loop_from: 0`, разовый — с `-1`.
- Кадров от 1 до 500. Задержка `delayMs`: целое, у `clock` до 65535 мс, у `frontal` не меньше 20 мс, у остальных до 600000.
- `ring`/`panel`/`oknix`: `{colors: [[r,g,b,w] × N], delayMs}`; цвета RGB без W дополняются нулём.
- `clock`: `{brightnesses: [0..255 × 32], delayMs}`. Порядок: 4 цифры × сегменты A–G (индексы 0–27), затем PLUS1, PLUS2, MINUS, DEGREE.
- `frontal`: `{colors: [[v,v,v] × 400], delayMs}`; дисплей чёрно-белый, градаций нет — пиксель либо включён (`[255,255,255]`), либо выключен (`[0,0,0]`); ненулевое значение сохраняется как включённое, цвет (r≠g или g≠b) отклоняется. GIF 25×16 строится из кадров при экспорте и отправке, импортированный GIF переводится в ч/б порогом (127): другой размер — масштаб к 25×16 (уменьшение усредняет по площади — BOX, увеличение — ближайший сосед), частичные кадры (дельта с disposal) композитятся с предыдущими, задержка кадра — из источника (минимум 20 мс).

## 3. Родные форматы (`animation_formats.py`)

**.led** (как `LedPattern::load` прошивки): строка — кадр, N цветов hex `RRGGBB` или `RRGGBBWW` и задержка мс; `loop` — начало цикла; `name X`; макросы-префиксы кадра `rotate`, `step1`, `step2`, `fill`, `unfill` разворачиваются в серию кадров; `gradient led1 цвет led2 цвет delay`. Строки `smooth`, `logsmooth`, `gammacorrection`, `background`, `no_size_optimization` читаются и не применяются. Ошибка разбора — `ValueError` с номером строки. Экспорт пишет `RRGGBBWW`.

**.scled** (как `ScLedPattern` прошивки): текст — 32 яркости (разделитель `|` допускается) и задержка, `loop`; бинарник — блоки `[0][32 яркости][задержка uint16 big-endian]` и `[1]` (метка цикла перед следующим кадром). Метка цикла после последнего кадра роняет прошивку, поэтому не пишется. Формат файла при импорте определяется по первому байту.

## 4. Отправка на колонку

`POST api/animations-play {platform, id, sn}` (`play_project`). Колонка должна быть той же платформы, что проект.

- `clock` — Push `draw_scled_animations` (имя и разбор нагрузки — `DrawSegmentAnimationParser` прошивки Мини 2): `{animations: [{name, base64_encoded_value, compression_type: "Gzip"}], animation_stop_policy}`; политика `RepeatLastTillNextDirective`, если задан цикл, иначе `PlayOnce`. Образца этой директивы в журнале нет, на колонке не проверена.
- `frontal` — GIF проекта кладётся в `state/animations/media/project.<platform>.<id>.gif`, Push `draw_led_screen` с URL `<адрес эмулятора>/emulator/api/animations-media?file=…`. Форма — как у настоящего сервера: `{animation_sequence: [{frontal_led_image: URL}, …], till_end_of_speech: false}` в конверте `client_action` + `IsLedSilent`; погода идёт парой кадров (температура + явление), эмоции — одним кадром.
- `ring` — Push `draw_animation_directive` с `PayloadRaw` `NAlice.TAnimationCapability.TDrawAnimationDirective` — `{Name: "draw_animation_directive", Animations: [{S3Directory: {Bucket: <адрес эмулятора>, Path: "emulator/api/animations-ring/<платформа>/<проект>"}}], SpeakingAnimationPolicy: "PlaySpeakingEndOfTts"}`, в конверте директивы `AnalyticsType: "draw_animation_directive"` (форма — как у настоящего сервера: образец погоды ведёт `Animations[0].S3Directory` на `Bucket: "https://quasar.s3.yandex.net"`, `Path: "animations/weather/cloudy"` с `SpeakingAnimationPolicy` = `PlaySpeakingEndOfTts` и тем же `AnalyticsType`; `AnimationStopPolicy: "RepeatTillScreenAlive"` — только для анимаций на время реплики, при разовом запуске не ставится). Файл кольца отдаёт `GET /emulator/api/animations-ring/<платформа>/<проект>/<хвост>` — экспорт `.led` на любой хвост, потому что имя файла, которое прошивка запрашивает внутри пути `S3Directory`, директивой не передаётся; без guard — колонка качает сама, каждый запрос — в журнале сервера (источник `animations`): запрошенный хвост и размер отдачи, отсутствующий проект — 404 и запись `warning`.
- `panel`, `oknix` — не отправляются: директивы прошивки с такой нагрузкой нет. Редактор, импорт и экспорт работают.

Адрес эмулятора для ссылок в директивах (`device_base_url`) — `local_domain` из `server.json` (`https://alica.lan` по умолчанию: имя резолвится в DNS сети, сертификат эмулятора ему выдан); домен не задан — схема и хост запроса интерфейса, тогда `localhost`/`127.0.0.1` отсекаются с ошибкой: колонка по ним файл не достанет.

Доставка — `runtime.push_action` (clock, frontal) или `runtime.send_message` с собранным Push (`ring`): живая сессия или мостовое соединение («Прозрачно»); экран колонки не подтверждается (`sent/unconfirmed`).

## 5. API

| Домен | Метод | Описание |
|---|---|---|
| `animations-platforms` | GET | платформы с колонками пользователя |
| `animations-projects` | GET `?platform=[&id=]` | список проектов платформы / проект |
| `animations-projects` | PUT | сохранить `{platform, id, title, kind, loop_from, frames}` |
| `animations-projects` | DELETE `?platform=&id=` | удалить проект (и его GIF) |
| `animations-import` | POST | `{platform, id, title, kind, filename, data_base64}`: .led/.scled/.gif до 2 МиБ; GIF другого размера масштабируется к 25×16 |
| `animations-export` | GET `?platform=&id=` | файл в родном формате: `.led`, `.scled` или `.gif` |
| `animations-play` | POST | отправка на колонку (раздел 4) |
| `animations-media` | GET `?file=` | GIF каталога и проектов |
| `animations-ring` | GET `/<платформа>/<проект>/<хвост>` | файл `.led` кольца для `draw_animation_directive`; без `X-Emulator` — запрос колонки (в логе сервера, источник `animations`) |
| `animations` | GET/PUT/DELETE/POST | каталог GIF-кадров станций; POST — Push `draw_led_screen` |

Запись — только с заголовком `X-Emulator: 1`. GIF строится и читается через Pillow (основная зависимость).

## 6. UI

Раздел «Анимации» группы «Эмулятор» (после «Каталога приложений») доступен всегда, даже без единой колонки — посылать анимацию будет некуда, но редактор, каталог, импорт и экспорт не блокируются. Подвкладки — все платформы реестра; при двух дисплеях — переключатель дисплея. На вкладке: каталог проектов (предпросмотр первого кадра миниатюрой — SVG-рендер кадра, у кольца/панели/окна/часов, маленький кадр GIF-матрицы у фронтального дисплея), редактор (SVG-холст под дисплей: сетка, кольцо, 7-сегментные часы; фронтальный холст чёрный — как дисплей, пиксель включается левой кнопкой мыши и выключается правой (контекстное меню подавлено), у часов — выбор яркости сегмента и «Погасить»/«Полная», у кольца/панели/окна — палитра RGB с ластиком, у фронтального дисплея и часов «Заливка кадра»; лента кадров, дубль/перемещение/удаление, задержка кадра, начало цикла), плеер предпросмотра, сохранение, экспорт, удаление. Для проигрываемых дисплеев (часы, фронтальная матрица, кольцо) — выбор колонки и «Проиграть на колонке»; нет подключённой колонки этой платформы — список неактивен, рядом одна короткая пояснительная строка (не на каждый клик). Импорт — файлом или вставленным текстом.

## 7. Добыча файлов анимаций

Каталоги прошивки в репозиторий не входят. Свои файлы с колонки или из распакованной OTA:

```
python tools/import_animations.py pull --remote <каталог на колонке> --dest <папка>     # adb pull
python tools/import_animations.py import --platform yandexmini_2 --kind clock <папка>   # в state/animations/
```

Расширение должно подходить дисплею (`ring`/`panel`/`oknix` — .led, `clock` — .scled, `frontal` — .gif 25×16); неподходящие файлы пропускаются с причиной. Каталог на колонке пользователь находит сам (`adb shell find / -name "*.scled"`).

## 8. Границы

- Реагирующие на звук анимации (эквалайзер, выбор стиля из приложения «Дом») не реализованы: нужна запись конфигурационных каналов с колонки.
- Раскладка 84 светодиодов панели Миди на растре 15×13 не воспроизводится: панель редактируется списком LED (12 в ряд), нумерация LED кольца — от верхней точки по часовой стрелке.
