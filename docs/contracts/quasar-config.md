# Quasar-конфиг: встроенный шаблон + замены

## Сборка ответа `/get_sync_info` (режим «Генерируемый»)

```
встроенный шаблон (quasar_defaults: общий дефолт + особенности платформы)
  → общие замены → замены платформы      (расширения, затем поставляемые ⊕ правки state)
  → замены аккаунта → локальный адрес → замены устройства   (только state)
  → динамика ({{…}} в строках, маркеры db/run) → итог
```

Локальный адрес — встроенный слой для устройств в «Эмуляции» и «Вместе» (`route_mode`
emulate/hybrid; в «Прозрачно» конфиг отдаёт Яндекс): `system_config.uniProxyUrl` =
`ws://<local_domain>/uni.ws` (`server.json local_domain`, по умолчанию `alica.lan`, читается на
каждую сборку; пустой — слоя нет; `quasar_rules.LOCAL_URLS`) и `system_config.pushd.xivaSubscribeUrl`
= `ws://<local_domain>/v2/subscribe/websocket` (пуш-канал quasar-realtime) и
`system_config.arpc_client.server_url` = `http://<local_domain>` (gproxy). Колонка применяет эти
адреса из get_sync_info без перезагрузки (pushd — при смене значения; после холодной загрузки
он начинает с `push.yandex.ru`, этот путь тоже обслуживается); пуш-канал эмулятор мостит к
`push.yandex.ru` в любом маршруте (`dispatcher.XIVA_PATH`), пути `/gproxy/*` и `/report` на
локальном домене обслуживает как `rpc.alice.yandex.net` и `report.appmetrica.yandex.net`
(`dispatcher.LOCAL_DOMAIN_PATHS`; ответ startup AppMetrica отдаёт отчёты на `http://<local_domain>`).
Остальные адреса колонка берёт из встроенного quasar.cfg и с сервера не меняет; WebSocket без TLS идёт на
HTTP-порт эмулятора. Так голос не требует подмены `uniproxy.alice.yandex.net` в DNS остальной
сети и сертификата. Условие — в DNS сети локальный домен указывает на IP сервера (пояснение в
легенде маршрутов, вкладка «Устройства»). Замена устройства этот адрес перебивает.

Одна функция — `quasar_rules.compose_config(runtime, platform, device, device_rules, trace,
render)`; ей пользуются ответ колонке, `generate`, просмотр итога в UI. Замены каждого слоя
применяются сверху вниз: нижняя сильнее. Слои расширений идут раньше пользовательских
(сначала расширения, затем свои) и только читаются.

## Замена

```json
{"id": "a1b2c3d4e5", "name": "Подписка", "path": "/subscription", "kind": "select",
 "value": "Включена", "options": {"Включена": {"enabled": true}, "Выключена": {"enabled": false}},
 "enabled": true}
```

- `path` — JSON Pointer (RFC 6901, библиотека `jsonpointer`): ключи с точкой
  (`com.yandex.io.sdk`) адресуются как есть, `/` и `~` экранируются `~1`/`~0`. Пустой путь
  (весь документ) и пустые сегменты запрещены. Недостающие объекты по пути создаются.
- Видов два:
  - `select` — **состояния узла**: `options` — имя → значение, `value` — имя текущего.
    Одно состояние — значение узла; два — переключатель вкл/выкл (первое — «вкл»); три и
    больше — выбор из списка;
  - `delete` — удалить ключ.
- Значение состояния — любой JSON. В строках — подстановки `{{…}}` (см. «Динамика»); строка из
  одной подстановки даёт её значение как есть (число, объект). Маркеры `{"db": "user.<путь>"}` и
  `{"run": "<скрипт>"}` — значение из реестра и stdout скрипта.
- `enabled: false` — замена хранится, но не применяется.
- Проверка при сохранении — pydantic-модель `RuleModel` (`validate_rules`): нужно хотя бы одно
  состояние с непустым именем, текущее — из списка, лишние поля запрещены; синтаксис подстановок
  `{{…}}` проверяется окружением bindings. Ошибка с полем и префиксом `Строка N:` (номер в списке),
  список не сохраняется. `id` выдаётся при сохранении, дубликаты переназначаются.

## Хранение

- Поставляемый набор — в пакете: `server_emulator/quasar_defaults/rules/common.json` и
  `rules/platforms/<платформа>.json`, формат `{"rules": [...]}` (подмена каталога — переменная
  `ALICA_QUASAR_RULES_DIR`, по образцу `ALICA_SCHEMAS_DIR`; не задана — каталог пакета);
  самообновление заменяет его целиком, правки не теряются. В общих — только то, что настоящий
  сервер отдаёт одинаково всем платформам (настройки аккаунта, эксперименты, подписка, ссылки
  на параметры); значения одной платформы (модели споттера, списки событий, период опроса) —
  в её файле, иначе общая замена навязывает их колонкам других платформ. Сверка — по ответам
  `get_sync_info` из журнала (`source=upstream`) колонок каждой платформы. Значения конкретной
  колонки или аккаунта в поставляемый набор не попадают.
- Правки state — `state/quasar/rules/common.json` и `rules/platforms/<платформа>.json` —
  дифф поверх поставляемого (`PUT quasar_rules` присылает список целиком, сохраняется только
  различающееся): правило, совпадающее с поставляемым, не хранится; поставляемое, отсутствующее
  в списке, — delete-маркер с его id (снимает его из набора, к конфигу не применяется;
  delete-правило state с чужим id — обычное удаление узла). Имя платформы — `[a-z0-9_.-]+`,
  `common` зарезервировано. Файл правок создаётся первым сохранением; удаление файла правок
  платформы не убирает поставляемые правила.
- Устройство: `state.quasar_overrides`; аккаунт: `quasar_overrides` пользователя (правила
  текущего формата, пути — внутри `/config/account_config/`) — только state.
- Расширения: `quasar/rules/common.json`, `quasar/rules/platforms/*.json` (только чтение).

## Динамика

Строки с подстановками `{{…}}` раскрываются окружением Jinja2 сценарного движка
(`scenario_engine/bindings.py`, строгое подмножество: путь контекста + не больше одного
фильтра реестра; операторов, вызовов и `{% %}`/`{# #}` нет). Корни контекста (`context_for`):
`now`, `now_ms`, `now_iso`, `uuid`, `device_id`, `device_name`, `platform`, `user_id` и вложенные
`device` (`name`, `sn`, `room`, `fields.*`) и `user` (`id`, `name`, `location.*`, `fields.*`)
реестра; каталог «Параметры» вкладывается в те же корни (`user.wifi_hash`,
`device.glagol_cert`, `server.*` — ключ параметра через точку; занятые реестром пути
не перезаписываются). Строка целиком из одной подстановки даёт её значение как есть
(число, объект — тип сохраняется), внутри текста — текст.

Привязка обязательна: подстановка не разрешилась, db-путь не найден, скрипт упал — правило
пропускается (колонка получает значение нижнего слоя, остальные замены работают), а ошибка
видна: закреплённое уведомление в шапке (`live_status` по `api/live`, `toast.js notify.pin` —
без крестика и автоскрытия, снимается следующей сборкой без ошибок), список ошибок в панели
устройства (`quasar_composed` `errors`), запись в журнале сервера («Лог», `source=quasar`,
дедуп склеивает повторы сборки). Пустой строки или 409 вместо значения нет. Незаполненный
параметр каталога «Параметры» (определение есть, значения нет ни на одном уровне цепочки —
так на новой установке: wifi_hash, координаты) — тот же пропуск, но текст «не заполнен
параметр X — вкладка «Параметры»».

Текст уведомления — по колонке: `Конфиг колонки · <имя> — ошибок: N · «<правило>»: <ошибка>`
(первая ошибка, при N > 1 — отсылка к вкладке «Quasar»); id закрепления `quasar:<SN>`.
Источник — `runtime.quasar_errors` (SN → ошибки последней сборки, только в памяти: после
перезапуска появляются при следующем опросе колонки).

Скрипт (`{"run": …}`) — subprocess из белого списка `state/quasar/scripts`, таймаут ~3 с;
переменные окружения QSN/QDEVICE_ID/QUSER_ID/QPATH/QCONTEXT(json); stdout → значение.

`render=False` — сборка без устройства (просмотр «Итог»): подстановки и маркеры остаются как есть,
ошибок нет.

### Новая установка

Поставляемые замены ссылаются на `{{user.wifi_hash}}`, `{{user.location.latitude}}`,
`{{user.location.longitude}}`, `{{device.name}}`, `{{device_id}}`. `device.name`, `device_id` и
заданные в реестре `user.location.*` берутся из реестра устройств и пользователей (реестр
сильнее каталога «Параметры»). Остального на пустом state нет: такая замена пропускается с
закреплённым уведомлением, колонка получает значение встроенного шаблона (`wifi_hash` и
координаты — примеры из исходного шаблона). Уведомления снимаются сами после заполнения
параметров и следующей сборки.

Узел `glagol.security` замены не задают: его кладёт поверх итога `glagol_security`
(quasar.py) — параметры `device.glagol_cert`/`device.glagol_key`, без них автоген
(`state.glagol_security`), поэтому новая установка обходится без них.

## Происхождение значений

`trace` — словарь «JSON Pointer → подпись»: `общие замены: <имя>`, `замены <платформа>: <имя>`
(с `(<id расширения>)` для слоёв расширений), `аккаунт <пользователь>: <имя>`, `локальный адрес <домен>: <имя>`, `устройство: <имя>`,
`(удалено)` для `delete`; динамика — `динамика {{путь}}`, `БД эмулятора: …`, `скрипт: …`.
Пути без подписи — из встроенного шаблона.

## API (admin, `/emulator/api/…`, `ui/api/quasar_config_api.py`)

- `quasar_platforms`:
  - `GET` → `{builtin_platforms, common_rules, platforms: [{platform, rules}], devices}`;
  - `GET ?builtin=<платформа>` → встроенный шаблон `{config, keys}` (имя вне белого списка — общий);
  - `GET ?compose=<платформа>` → итог без устройства (`render=False`) с `origins`;
  - `POST {action: "create", platform}`, `POST {action: "rename", platform, to}`,
    `DELETE ?platform=` — файлы замен платформ.
- `quasar_rules`:
  - `GET ?layer=common|platform:<имя>|device:<SN>` → `{rules, inherited}`; `rules` —
    поставляемое ⊕ правки state: флаги `shipped`/`modified`, снятые — `removed` с исходником
    `base` (для «сбросить к поставляемому»); `inherited` — `[{origin, rules}]` слоёв
    расширений; для устройства ещё `platform` (правила — только state, без флагов);
  - `PUT {layer, rules}` — список целиком (поставляемое ⊕ правки, флаги игнорируются),
    сохраняется дифф; у устройства пустой список удаляет поле. После сохранения —
    `push_update_config` колонкам слоя с живой сессией (общий слой — всем, платформа — её
    устройствам), ответ `pushed: [SN]`; так же после `PUT quasar_source`.
- `quasar_composed?device=SN[&raw=1]` → итог устройства `{platform, config, origins, warnings, errors}`;
  `raw=1` — без подстановки (`render=False`, `errors` пустой), иначе `errors` — ошибки источников
  последней сборки `{layer, rule, path, error}`; ошибка сборки (вне источников) — `{error}`.
- `GET /emulator/api/live` (общий опрос шапки) — поле `quasar_errors: [{sn, name, errors}]`:
  колонки с ошибками последней сборки (те же `errors`); пусто — уведомлений нет.

## UI (вкладка «Quasar»)

Слева шаги сборки — «Шаблон», «Общие замены», «Замены платформы», «Замены устройств», «Итог»
(на узком экране — сегменты сверху). Без горизонтальной прокрутки на 400 px.

- «Шаблон» — встроенный шаблон выбранной платформы, только чтение.
- Замены — таблица: галочка вкл/выкл · имя · узел JSON · значение · действия (иконки
  «Редактировать», «Выше», «Ниже», «Удалить»). Поставляемые правила помечены у имени
  («поставляемое», правка state — «изменено», снятое — «снято»); «Сбросить» возвращает
  исходное поставляемое правило, порядок — поставляемые, затем свои (у поставляемых
  «Выше»/«Ниже» отключены). Значение по числу состояний: одно — кнопка с кратким значением
  (подстановки — теги), два — переключатель, больше — список; переключатель и список меняются
  прямо в строке. Каждое действие сохраняется сразу (`PUT quasar_rules` — список целиком,
  сервер хранит только дифф поверх поставляемого). Окно замены (`<dialog>`): имя, узел
  (подсказки — пути итога), вид «Состояния | Удалить ключ», список состояний (текущее · имя ·
  значение — текст или JSON), кнопки-теги подстановок (токены и параметры каталога) вставляют
  `{{…}}` в поле значения, «Включена». Замены расширений — отдельной группой, только чтение.
- «Замены платформы» — выбор платформы (встроенные и с заменами) и меню платформ.
- «Замены устройств» — список колонок; у выбранной — источник конфига (см. ниже), для
  «Генерируемый» — замены устройства, ошибки источников сборки (правило пропущено — нижний
  слой стоит) и итог устройства: клик по строке итога — новая замена с этим путём.
- «Итог» — сборка без устройства с подсказкой происхождения по наведению.
- Несохранённое состояние есть только у редактора «Свой ответ»; уход с него спрашивает
  подтверждение.

## Замены аккаунта

На настоящем сервере `config` собирается из частей с разными владельцами: `account_config`
(аккаунт), `device_config` (устройство), `system_config` (сервер). Эмулятор повторяет это слоем
замен владельца устройства.

- Пути — только внутри `/config/account_config/` (сам узел целиком не заменяется): иначе
  `QuasarConfigError` при сборке и `ValueError` (HTTP 400) при сохранении.
- Чтение — `GET identities` (`users[].quasar_overrides`); запись — `POST identities`
  `{"operation": "user_quasar_overrides", "id", "quasar_overrides": [...]}`, список целиком,
  пустой — очищает.
- Хранение — meta `identity_user_quasar` (`{user_id: [...]}`); правка имени слой не трогает,
  удаление пользователя удаляет слой. У устройства без владельца слоя нет.
- UI — карточка пользователя, вкладка «Настройки аккаунта».

## Встроенный шаблон

`server_emulator/quasar_defaults/` — полный ответ без захвата, перенесённый из исходников
quasar-server (MIT; commit и пересборка — `tools/build_quasar_defaults.py` и README рядом):

- `common.json` — config (account_config/device_config/system_config) +
  `alice_pro_subscription {enabled: true, ttl: 31536000}` + `subscription {mode: "transaction"}`
  + `tags: []`; `device_config.name` — токен `{{device.name}}`;
- `platforms/<платформа>.json` — merge-patch поверх common для 13 платформ; chiron/magritte —
  `hybrid_request_factory`: `supported_frames` — объект и удаление `hybrid_voice_inputs`.

Платформа шаблона — `device_platform`: `device.profile.platform` → платформа, которую колонка
сообщила при опросе (query `platform`, хранится в `state.reported_platform`) → пусто (общий).

## Источник конфига устройства

Каждое устройство выбирает, откуда брать ответ на `GET /get_sync_info`. Режим хранится в
`state.quasar_source` устройства, свой ответ — в `state.quasar_custom`, последний ответ Яндекса —
в `state.quasar_direct_last` (`{ts, status, body}`, тело — распакованный JSON). Отсутствие поля —
режим `generated`.

| Метка | Режим | Что получает колонка |
|---|---|---|
| **Генерируемый** | `generated` (по умолчанию) | конфиг, собранный `compose_config`: шаблон и замены (см. выше) |
| **Напрямую** | `direct` | ответ настоящего `quasar.yandex.net` без изменений; обмен — в «Журнал» (`source=upstream`) по опции «Запись» устройства; успешный JSON сохраняется в `state.quasar_direct_last` |
| **Свой** | `custom` | `state.quasar_custom` как есть: без замен, glagol.security и группы стереопары; нет сохранённого или в нём нет `config` → 409 `quasar_custom_not_set` |

Маршрут API (`ui/api/quasar_config_api.py`, домен `quasar_source`):

- `GET ?sn=` → `{mode, direct_last, custom, replace, transparent, can_fetch}`; `can_fetch` — запомнены ли
  заголовки последнего опроса этой колонки; `replace` — правила замен «Напрямую» (по умолчанию `[]`);
  `transparent` — галочка «И в прозрачном маршруте» (по умолчанию `false`);
- `PUT {sn, mode?, custom?, replace?, transparent?}` — сохранение режима, своего ответа, замен и/или
  галочки под `runtime.lock` (custom — JSON-объект с объектом `config`, иначе 400; `replace` — см.
  ниже; `transparent` — bool, иначе 400);
- `POST {sn, action: "generate"}` — ответ, который собрал бы `compose_config` (как отдаётся колонке,
  включая `group`); ничего не сохраняет;
- `POST {sn, action: "fetch"}` — запрос оригинальному серверу с запомненными заголовками и query
  этой колонки; тело ответа возвращается, ничего не сохраняет; заголовков нет → 409.
- `POST {sn, action: "push"}` — принудительный перезапрос конфига: Push `push_update_config`
  в живую WS-сессию устройства (колонка сама сделает `get_sync_info`); нет живой сессии →
  409 `push_no_session`.

### Замены в ответе «Напрямую»

Своё у каждого устройства: `state.quasar_direct_replace = [{enabled, pattern, replace}, …]`, порядок
важен (редактор — кнопка «Замены в тексте» в панели «Напрямую»). `PUT {sn, replace}` проверяет каждый
`pattern` через `re.compile` (и шаблон `replace` — ссылки на группы); ошибка → 400 с текстом
`Строка N: <ошибка re>`, ничего не сохраняется. Пустой `pattern`, больше 50 правил, `pattern`/`replace`
длиннее 2000 символов — тоже 400. Пустой список удаляет поле.

Применение (`quasar_replace.py`, из `Dispatcher.direct_sync_info`): только при статусе 200 и только
включённые правила, по порядку. Тело распаковывается как в `decoded_json` (gzip/deflate), берётся
текст UTF-8, к нему по очереди `re.sub(pattern, replace, text)` (синтаксис Python `re`: `\1`,
`\g<name>`). Если текст изменился, колонке уходит несжатое тело без `Content-Encoding` и с верным
`Content-Length`; не изменился — оригинал байт-в-байт. Защита: исходное тело было JSON-объектом, а
после замен перестало им быть (или regex упал во время работы) → колонке уходит **исходный** ответ,
в `runtime.recent` пишется `{kind: quasar_replace, error}` с номером последнего применённого правила.

`state.quasar_direct_last.body` остаётся ответом Яндекса; если замены что-то изменили, добавляются
`body_sent` (JSON после замен) и `replaced` (число сработавших правил). Журнал трафика пишет ответ
Яндекса (то, что получил эмулятор): разделения «оригинал/отправлено» у записи журнала нет.
Тесты: `tests/test_quasar_direct_replace.py`.

#### «И в прозрачном маршруте»

`state.quasar_direct_transparent: bool` (своё у каждого устройства, по умолчанию `false`, `false`
хранится отсутствием поля). Включена → при маршруте устройства «Прозрачно» (`proxy`) ответ
`get_sync_info` обрабатывается так же, как в «Напрямую» (`Dispatcher.direct_sync_info`: пересылка,
замены, защита JSON, `quasar_direct_last`, журнал по опции «Запись», ошибка пересылки — 502).
Условия — все сразу: источник устройства `direct`, галочка включена, хост (после алиасов)
`quasar.yandex.net`, путь `/get_sync_info`, устройство опознано. Иначе, как и весь остальной
трафик маршрута, запрос идёт прямым проходом байт-в-байт; WS не затрагивается. В «Эмуляции» и
«Вместе» галочка ни на что не влияет: замены «Напрямую» там работают как обычно.

Заголовки последнего `get_sync_info` каждого устройства (включая `Authorization`) запоминаются
**только в памяти** `runtime` (по SN), в любом режиме опроса; на диск и в state не пишутся. При
маршруте устройства «Прозрачно» запросы идут в Яндекс напрямую: источники
«Генерируемый» и «Свой» не применяются, «Напрямую» — только с галочкой «И в прозрачном маршруте»
(см. выше). Тесты: `tests/test_quasar_source.py`.
