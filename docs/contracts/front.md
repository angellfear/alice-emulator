# Фронт TLS

Код: `server_emulator/front.py`.

## Обзор

TCP-фронт публичного TLS-порта: по SNI отдаёт соединение эмулятору, в туннель или отклоняет.

## Маршрутизация по SNI

Публичный TLS-порт слушает сырой TCP-фронт (`front.py`), а не `TCPSite` напрямую. На каждое
соединение фронт читает ClientHello (до 32 КиБ, без расшифровки) и достаёт SNI. Имя покрыто
сертификатом сервера (DNS-SAN листового PEM, wildcard ровно на один уровень — `cert_covers`,
RFC 6125), SNI нет, или имя — литеральный IP, имя локальной сети или `server.json local_domain` → соединение сплайсом уходит внутреннему
aiohttp-слушателю с тем же `ssl_context` (эphemeral порт на 127.0.0.1; накопленные байты идут
первыми). Иначе (например `strm-*.strm.yandex.net`, не покрытый wildcard `*.yandex.net` — из-за
этого колонка не могла открыть TLS к музыке) — решает политика `server.json front_uncovered`
: `tunnel` (по умолчанию) — слепой TCP-туннель к настоящему адресу хоста: A-записи
у внешних DNS (`front_dns`, aiodns), порт публичного слушателя, байт-в-байт, таймауты соединения
и простоя (300 с); адрес самого сервера выкидывается (защита от петли —
`upstream.resolver.local_addresses`), содержимое фронту не видно. `allowlist` — туннель только
доменам из `front_allow` (wildcard `*.` на один уровень, тот же `cert_covers`), прочие
отклоняются. `block` — все непокрытые отклоняются: соединение закрывается сразу после чтения
SNI, TLS не состоялся. Сертификат не читается (SAN пуст) — всё сплайсом, политика не применяется.
HTTP-порт (80) фронт не обрабатывает. Выключатель `front: false`
возвращает прежний прямой `TCPSite` (без фронта применение тоже требует перезапуска — как прочие
настройки слушателей).

Политика (режим и лист) применяется **без перезапуска**: фронт читает `front_uncovered` и
`front_allow` из `server.json` на каждое соединение (`front.py::_policy`); уже открытые
соединения не затрагиваются. UI — «Дополнительно → Сервер», блок «Домены вне сертификата»:
три режима, при «по листу» — поле (1 домен на строку) и список зафиксированных; кнопка
«Применить» сохраняет без перезапуска (`api/server-front`). `PUT api/server` эти ключи не
обнуляет — форма их не отправляет, значения берутся из файла.

Реальный адрес колонки сохраняется таблицей `Front.peers` (исходящий сокет сплайса →
оригинальный пир); `serve()` привязывает её к `runtime.client_peer`, и `dispatcher.client_ip`
отдаёт обработчикам настоящий IP вместо 127.0.0.1. Каждый непокрытый домен (туннель или
отклонение) фиксируется в `Front.seen` (имя → счётчик, память с запуска фронта) — наружу через
`runtime.front_observed`; имена сертификата — `runtime.front_sans`. Оба отдаёт GET
`api/server-front`; список в UI — с кнопкой «Добавить» (вносит домен в лист). События —
в журнал сервера: info о старте (порт, число имён в сертификате), warning «Домен не найден
в сертификате — соединение идёт туннелем» (адрес в detail, повторы склеивает журнал), warning
«Домен … не в сертификате — соединение отклонено» (режим в detail), error при неудаче туннеля
(DNS, нет адресов после фильтра петли, соединение не прошло). Счётчик туннелей по хостам —
`Front.tunnels` (в памяти) и ×N в журнале. Потоки музыки поставщика (`storage.yandex.net`,
`*.strm.yandex.net`) туннелируются штатно — для них уровень info, а в сообщении общий шаблон
домена (`*.strm.yandex.net`), а не конкретное имя потока: оно меняется на каждый трек
(`strm-mar-NNN` и т.п.), иначе на каждый NNN была бы своя запись журнала.

## Остановка

`Front.stop()` закрывает всё сразу и ничего не ждёт: слушатель закрывается, клиентские сокеты
закрываются, задачи-обработчики соединений отменяются (в `finally` `_connection` закрывает и
стороны туннеля). Ожидать завершения соединений здесь нельзя: туннель может ждать upstream хоть
вечно — `wait_closed()` с живым соединением не заканчивается никогда. Общий проход остановки
сервера (код выхода из `serve()`, `on_cleanup`, дочерние процессы голосового стека) — в
докстринге `control.py`; фронт укладывается в него без собственных ожиданий.
