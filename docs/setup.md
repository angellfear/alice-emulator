# Установка и настройка

## Требования

- Python 3.11+
- Windows 10+ или Linux

## Установка

```powershell
python -m pip install -e ".[test]"
```

Зависимости эмулятора (aiohttp, protobuf, langchain/langgraph, mcp, hassil и др.) — в `pyproject.toml`.

| Extra | Что включает |
|---|---|
| `.[test]` | pytest и зависимости тестов |
| `.[windows]` | pystray, Pillow — трей Windows (TASK-045) |

Локальный ASR/TTS (sherpa-onnx) — отдельные сервисы голосового стека, см. `tools/builder_asr.py`,
`tools/builder_tts.py` и `tools/builder-speech-requirements.txt`.

## Первый запуск: картинки с сайта умного дома, протокол из библиотеки станции

Описаний протокола (`server_emulator/schemas/*.pb`) и картинок устройств (`server_emulator/ui/img/devices/*.webp`)
в репозитории нет. Сервер стартует и без них:
UI и admin-API работают, а WS и протокольные HTTP-обработчики отвечают `setup_required` (WS закрывается с этой
причиной, HTTP — 503 JSON).

- **Картинки — с сайта умного дома Яндекса** (`https://iot.quasar.yandex.ru/iot/`, вход не нужен). Права на них
  принадлежат ООО «Яндекс», поэтому эмулятор скачивает их только по согласию пользователя: галочка в окне
  настройки, `{"accept": true}` в `POST api/setup/images`, `--accept` в CLI. Фоновой загрузки нет. Эмулятор находит
  в CSS страницы картинки устройств и скачивает недостающие. Необязательны: без них, без сети или если картинки
  нет на сайте показывается силуэт (колонка, колонка с экраном, ТВ, хаб). Запросы идут только по https и только
  на `iot.quasar.yandex.ru` и `pudya.yastatic.net`.
- **Протокол — один файл на выбор.** Обязателен.
  - `libquasar_daemons.so` станции: лежит в APK `centaur-app-launcher.apk` (пакет `ru.yandex.quasar.centaur_app`)
    в папке `lib/arm64-v8a/`; APK — zip, его распаковывает любой архиватор. Эмулятор находит в библиотеке
    сериализованные дескрипторы.
  - zip-архив с `.proto` (собираются `grpc_tools.protoc` из зависимости `grpcio-tools`; корень импортов
    определяется сам, сломанные лишние файлы пропускаются) и/или скомпилированными наборами `.pb` / `.desc` /
    `.protoset` (FileDescriptorSet).

  Результат — `schemas/alica-<хеш>.pb` (полный набор, рядом `.pb.json` со сводкой) и `schemas/alice-api.pb`
  (выборка `NAlice.NAliceApi`).

Как настроить:

- **UI.** Окно «Настройка эмулятора» (шаг 1 — картинки, шаг 2 — протокол) открывается само, пока нет протокола
  или пока нет картинок и окно в этом браузере не закрывали. Без протокола остаётся плашка «Нужна настройка».
  Состояние и повторная загрузка — «Дополнительно → Настройка». После разбора перезапускать сервер не нужно.
- **CLI.** `python -m server_emulator.protocol_import <libquasar_daemons.so | архив.zip>` — протокол;
  `python -m server_emulator.device_images --accept` — картинки (без `--accept` печатает условие и выходит).

Файл протокола читается потоком во временный файл в каталоге данных и удаляется после разбора, никуда не
отправляется.
Результат пишется атомарно в игнорируемые Git каталоги. Каталоги можно переопределить переменными окружения
`ALICA_SCHEMAS_DIR` и `ALICA_IMAGES_DIR` (по умолчанию — `server_emulator/schemas/` и
`server_emulator/ui/img/devices/`).

Тесты: протокол нужен большинству тестов. Задайте `ALICA_PROTOCOL_SOURCE=<libquasar_daemons.so или zip>` — схемы
соберутся один раз;
без схем тесты, зависящие от протокола, пропускаются. Картинки тестам не нужны.

## Запуск

```powershell
python -m server_emulator.server
```

UI: `http://127.0.0.1:8877/emulator/`. HTTP/WS устройства обслуживаются на том же порту, для
UniProxy используется `/uni.ws`.

| Параметр | Назначение |
|---|---|
| `--host 0.0.0.0` | принимать подключения по сети |
| `--port N` | порт (по умолчанию 8877) |
| `--state DIR` | каталог данных (по умолчанию `server_emulator/state/`, в Git не попадает) |
| `--cert FILE --key FILE` | HTTPS/WSS |

Подробнее: [server_emulator/README.md](../server_emulator/README.md).

## Порты и сертификат (TASK-042, state/server.json)

Адрес, порты и сертификат хранятся в `state/server.json` и переживают перезапуск; аргументы
командной строки перекрывают файл (какие поля перекрыты — в статусе сервера):

| Ключ | По умолчанию | Назначение |
|---|---|---|
| `host` | `0.0.0.0` | адрес слушателя |
| `port` | `443` | основной порт (TLS для колонок) |
| `ssl` | `true` | TLS на основном порту |
| `cert` / `key` | — | PEM-сертификат и ключ (ключ может лежать в том же файле — тогда `key` пустой) |
| `http_port` | `80` | второй слушатель без TLS (0 — выключен); колонки ходят по HTTP на `quasar.local` |

Правки — во вкладке «Дополнительно → Сервер» или правкой файла. Если сервер не поднялся с новыми
настройками (порт занят, битый сертификат), прежние возвращаются автоматически и сервер перезапускается.

## Настройка DNS устройств

На устройствах Алиса следующие имена должны разрешаться в LAN IP компьютера с эмулятором:

- `quasar.local` — HTTP backend
- `uniproxy.local` — WebSocket (голос, состояние)
- `rpc.local` — RPC (опционально)

Hosts на компьютере для этого недостаточно — нужна настройка DNS на роутере или устройстве.
Суффикс `.local` может обслуживаться mDNS; проверьте разрешение на устройстве. Программа DNS,
firewall и устройства не изменяет.

## TLS

Для HTTPS/WSS передайте PEM-сертификат (с цепочкой) и ключ параметрами `--cert` и `--key`.
Сертификаты и ключи в репозиторий не добавляются (см. `.gitignore`).

## Аутентификация

По умолчанию выключена (режим локальной лаборатории).

```powershell
python -m server_emulator.auth
```

Создаёт администратора и включает обязательный вход для панели и API. Роли: admin/user, сессии
HttpOnly+SameSite=Strict. Секреты провайдеров можно задавать ссылками `env:ИМЯ`. До включения входа
для удалённого доступа используйте SSH-туннель.

## Бэкап

Остановите сервер и скопируйте каталог `--state` (настройки, сценарии, пользователи, устройства, журналы).
