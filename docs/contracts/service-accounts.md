# Авторизация в сервисах: реестр аккаунтов и токены колонок

Код: `server_emulator/service_accounts.py` (реестр), `server_emulator/account.py` (QR-вход и
обмен x_token на токен сервиса), `server_emulator/ui/api/service_accounts.py` (API),
`server_emulator/ui/service_accounts.js` (вкладка). Тесты: `tests/test_service_accounts.py`,
`tests/test_account_import.py` (QR против подделки паспорта), `tests/test_provider_login.py`.

## Обзор

Вход в сторонние сервисы для поставщиков данных: Яндекс (вход по QR — несколько аккаунтов,
один основной) и Spotify (вход через точки login поставщика, redirect на панель). Отдельно —
токены колонок: колонка сама приносит свой OAuth-токен, их по SN собирает ядро, реестр —
запасной источник, когда у колонки своего нет.

## Хранение

- Аккаунты: `state/service_accounts/index.json` (метаданные: id, service, title, default,
  created) + файл секретов на аккаунт `state/service_accounts/<id>.json` (токены и кеш
  токенов сервисов в формате `account.AccountSession`). Секреты наружу API не отдаются:
  в ответах, журналах и текстах ошибок только статусы. Пароли не хранятся вообще.
- Токены колонок: БД состояния (meta `yandex_oauth_columns` — карта sn → токен, запасная
  `yandex_oauth`), кеш ядра `music._CAPTURED`, гидратация при старте — `music.load_token`.

## Вход

- **Яндекс — только QR.** `POST api/service-accounts {op: "qr_start"}` → `{link, qr}`:
  `qr` — data-URI PNG, QR-код ссылки подтверждения, который панель показывает прямо
  в себе — код сканирует приложение Яндекса на телефоне (как в Home
  Assistant-интеграции YandexStation), страница входа в браузере не открывается.
  `{op: "qr_poll"}` (периодически, окно 300 с) → `waiting`/`done`. Механика —
  `account.AccountSession.qr_start/qr_poll` (страница pwl-yandex, magic-код, обмен
  cookies сессии на x_token), scratch-сессия — временный файл `_qr.json`, готовый
  вход переезжает в реестр (`add`) и scratch удаляется. Повторный вход с тем же
  логином (display_login) обновляет запись, а не плодит дубликаты.
- **Spotify** — точки login плагина (`docs/contracts/providers.md`): токены колбэка и
  refresh попадают в реестр (сервис `spotify`; с логином профиля — свой аккаунт, без —
  перезапись основного).

## Мультиаккаунты

Аккаунтов на сервис — сколько нужно; один помечен основным (`default`): первый добавленный
становится основным автоматически, переключение — `{op: "default", id}`, удаление основного
передаёт флаг преемнику того же сервиса. Основной аккаунт Яндекса обслуживает поставщиков
без токена колонки (музыка), конфигуратор импортирует значения по всем аккаунтам сразу
(`account.linked_sessions`).

## Перенос при первом запуске

Старые сессии входа `state/account/sessions/*.json` (кнопка «Яндекс» у пользователя)
становятся аккаунтами «yandex», файлы удаляются; папка `account/` сносится, когда опустела.
Meta `provider_login:<ext_id>` плагинов переезжает в реестр лениво при первом чтении статуса
поставщика (расширения к старту сервера не загружены).

## API

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/emulator/api/service-accounts` | `{accounts: [{id, service, title, default, created, login}], columns: [{sn, platform, ip, ts}]}` — статусы без секретов; `columns` — копилка токенов колонок: платформа из реестра устройств, ip и время — из деталей захвата (адрес колонки на момент запроса), токены наружу не идут |
| POST | `/emulator/api/service-accounts` | `{op}`: `qr_start` → `{link}`; `qr_poll` → `{state: waiting\|done, id?, title?, default?}`; `default {id}`; `remove {id}`; `forget {sn}` — удалить захваченный токен колонки (с запасным, если это тот же; неизвестный SN — 400); неизвестный op — 400 |

## UI

Вкладка «Настройки → Авторизация в сервисах» (`service_accounts.js`): карточка Яндекс
(список аккаунтов с радио основного, вход по QR с опросом), карточка Spotify (кнопка
открывает страницу входа поставщика, статус по точке `login_status`), панель «Токены
колонок» — строка на колонку: SN, платформа, адрес на момент захвата и «Удалить»
(удалённый токен колонка принесёт снова при следующем обращении к Яндексу). Поставщики
данных показывают у себя кнопку-редирект на эту вкладку.

## Не реализовано

- Выход из аккаунта, кроме удаления записи (токены живут, пока жив refresh у сервиса).
- Другие сервисы, кроме Яндекс и Spotify, — добавляются записью в реестр и точками
  login у поставщика без правки ядра.
- Устройство не подключено, токены колонок пусты — QR-аккаунт остаётся единственным
  источником для музыки; обратный запасной путь (последний захваченный) живёт в ядре,
  без отдельной настройки.
