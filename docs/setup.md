# Установка и настройка

## Требования

- Python 3.11+
- Windows 10+ или Linux

## Установка

Скрипт — `install.bat` (Windows) или `install.sh` (Linux): проверяет Python 3.11+, при запуске вне
клона клонирует репозиторий на тег последнего релиза в подпапку `alice-emulator`, создаёт `.venv`
и ставит пакет editable (`pip install -e ".[emulator]"`). Git CLI нужен только на этой первичной
установке; версия и самообновление работают без него. Для приватного репозитория клон идёт
с учётными данными git пользователя — скрипт их не спрашивает и не хранит. Повторный запуск
безопасен: существующий клон и `.venv` не пересоздаются.

Вручную:

```powershell
git clone https://github.com/angellfear/alice-emulator.git   # или --branch vX.Y.Z — конкретный релиз
cd alice-emulator
python -m venv .venv
.venv\Scripts\python -m pip install -e ".[emulator]"       # Linux/macOS: .venv/bin/python
```

Editable-установка важна для самообновления: после переключения рабочей копии на новый
тег код подхватывается без переустановки. Зависимости эмулятора (aiohttp, protobuf,
langchain/langgraph, mcp, dulwich, hassil и др.) — в `pyproject.toml`; `server_emulator/requirements.txt`
только отсылает к нему.

Установка из zip-архива GitHub (без `.git`) работает, но не обновляется автоматически: версия берётся
из `.release-please-manifest.json`, обновление — скачиванием нового архива и заменой папки (данные
в `state/` переносятся отдельно).

| Extra | Что включает |
|---|---|
| `.[emulator]` | полный набор для запуска эмулятора (включая трей Windows) — им ставят скрипты установки |
| `.[test]` | pytest и зависимости тестов |
| `.[windows]` | pystray, Pillow — трей Windows |

Локальный ASR/TTS (sherpa-onnx) — отдельные сервисы голосового стека, см. `tools/builder_asr.py`,
`tools/builder_tts.py` и `tools/builder-speech-requirements.txt`.

## Первый запуск: картинки с сайта умного дома, протокол из библиотеки станции

Описаний протокола (`server_emulator/schemas/*.pb`) и картинок устройств (`server_emulator/ui/img/devices/*.webp`)
в репозитории нет. Сервер стартует и без них:
UI и admin-API работают, а WS и протокольные HTTP-обработчики отвечают `setup_required` (WS закрывается с этой
причиной, HTTP — 503 JSON).

- **Картинки — с сайта умного дома Яндекса** (`https://iot.quasar.yandex.ru/iot/`, вход не нужен). Права на них
  принадлежат ООО «Яндекс», поэтому эмулятор скачивает их только по согласию пользователя: галочка в окне
  настройки, `{"accept": true}` в `POST api/setup/images`, `--accept` в CLI. Фоновой загрузки нет. Эмулятор находит
  в CSS страницы картинки устройств и скачивает недостающие. Необязательны: без них, без сети или если картинки
  нет на сайте показывается силуэт (колонка, колонка с экраном, ТВ, хаб). Запросы идут только по https и только
  на `iot.quasar.yandex.ru` и `pudya.yastatic.net`.
- **Протокол — один файл на выбор.** Обязателен.
  - `libquasar_daemons.so` станции: лежит в APK `centaur-app-launcher.apk` (пакет `ru.yandex.quasar.centaur_app`)
    в папке `lib/arm64-v8a/`; APK — zip, его распаковывает любой архиватор. Эмулятор находит в библиотеке
    сериализованные дескрипторы.
  - zip-архив с `.proto` (собираются `grpc_tools.protoc` из зависимости `grpcio-tools`; корень импортов
    определяется сам, сломанные лишние файлы пропускаются) и/или скомпилированными наборами `.pb` / `.desc` /
    `.protoset` (FileDescriptorSet).

  Результат — `schemas/alica-<хеш>.pb` (полный набор, рядом `.pb.json` со сводкой) и `schemas/alice-api.pb`
  (выборка `NAlice.NAliceApi`).

Как настроить:

- **UI.** Окно «Настройка эмулятора» (шаг 1 — картинки, шаг 2 — протокол) открывается само, пока нет протокола
  или пока нет картинок и окно в этом браузере не закрывали. Без протокола остаётся плашка «Нужна настройка».
  Состояние и повторная загрузка — «Дополнительно → Настройка». После разбора перезапускать сервер не нужно.
- **CLI.** `python -m server_emulator.protocol_import <libquasar_daemons.so | архив.zip>` — протокол;
  `python -m server_emulator.device_images --accept` — картинки (без `--accept` печатает условие и выходит).

Файл протокола читается потоком во временный файл в каталоге данных и удаляется после разбора, никуда не
отправляется.
Результат пишется атомарно в игнорируемые Git каталоги. Каталоги можно переопределить переменными окружения
`ALICA_SCHEMAS_DIR` и `ALICA_IMAGES_DIR` (по умолчанию — `server_emulator/schemas/` и
`server_emulator/ui/img/devices/`).

Тесты: протокол нужен большинству тестов. Задайте `ALICA_PROTOCOL_SOURCE=<libquasar_daemons.so или zip>` — схемы
соберутся один раз;
без схем тесты, зависящие от протокола, пропускаются. Картинки тестам не нужны.

## Запуск

```powershell
python -m server_emulator.server
```

Готовые скрипты: `start.bat` (Windows, трей без консоли) и `start.sh` (Linux, при отсутствии `.venv`
сначала запускает установку). Ярлык на рабочий стол — `tools/install_autostart.ps1 -Desktop`.

UI: `http://127.0.0.1/emulator/` — порт 80 без TLS. Устройства обслуживает порт 443: это тот же
сервер, фронт по SNI решает — отвечает эмулятор или туннель в облако; для UniProxy используется
`/uni.ws`.

| Параметр | Назначение |
|---|---|
| `--host 0.0.0.0` | принимать подключения по сети |
| `--port N` | TLS-порт устройств (по умолчанию 443) |
| `--http-port N` | второй порт без TLS, панель (по умолчанию 80; `0` — выключен) |
| `--state DIR` | каталог данных (по умолчанию `server_emulator/state/`, в Git не попадает) |
| `--cert FILE --key FILE` | HTTPS/WSS (сертификат на имена Яндекса) |
| `--no-ssl` | без TLS на основном порту (отладка) |

Подробнее: [server_emulator/README.md](../server_emulator/README.md).

Работа 24/7 на Linux-сервере — служба systemd: [deploy.md](deploy.md).

## Самообновление

Сервер сам проверяет релизы GitHub (раз в `interval_hours`, по умолчанию 12) и показывает кнопку
«Обновление vX.Y.Z» в навигации, когда вышел новый релиз. Обновление — только по кнопке: окно
показывает заметки релиза, перед переключением делает бэкап `state/` (zip в `state/backups/`,
хранится 5), переключает рабочую копию на тег и перезапускает сервер. Откат на предыдущий тег —
кнопкой в том же окне при неудаче; автоматически ничего не ставится.

Настройки — во вкладке «Дополнительно → Сервер», блок «Обновление»: галочка «Включить
автообновление» (отключает только фоновую проверку — кнопка-индикатор и «Проверить сейчас»
работают всегда, обновление всегда в ручном режиме) и канал (стабильные / бета с пререлизами).
Остальные параметры (репозиторий `owner/name`, интервал, кто поднимает сервер, токен GitHub)
не редактируются в форме и остаются в значениях по умолчанию. Репозиторий приватный — без токена
проверка отвечает «недоступен»: токен (строка или `env:ИМЯ`) задаётся в настройках
(`self_update.token`).

Если в рабочей копии есть правки отслеживаемых файлов, кнопка обновления неактивна со списком
файлов; кнопка «Отложить правки и обновить» убирает их в git-stash и обновляет. Установка из
zip-архива (без `.git`) обновлениями не пользуется — только заменой архива целиком; данные в
`state/` при этом переносятся вручную.

## Порты и сертификат

Адрес, порты и сертификат хранятся в `state/server.json` и переживают перезапуск; аргументы
командной строки перекрывают файл (какие поля перекрыты — в статусе сервера):

| Ключ | По умолчанию | Назначение |
|---|---|---|
| `host` | `0.0.0.0` | адрес слушателя |
| `port` | `443` | основной порт (TLS для колонок) |
| `ssl` | `true` | TLS на основном порту |
| `cert` / `key` | — | PEM-сертификат и ключ (ключ может лежать в том же файле — тогда `key` пустой) |
| `http_port` | `80` | второй слушатель без TLS (0 — выключен); колонки ходят по HTTP на `quasar.yandex.net` |
| `front` | `true` | фронт TLS: SNI решает — эмулятор или туннель (см. «Фронт TLS» ниже) |
| `front_dns` | `8.8.8.8, 1.1.1.1` | внешние DNS для адресов туннелей фронта |

Сертификат и ключ можно указать путём на компьютере с эмулятором (в кавычках из «Копировать как путь» тоже
работает; относительный путь отсчитывается от папки данных) или загрузить кнопкой «Загрузить…» во вкладке «Сервер»:
файл сохраняется в `state/certs/`, в поле подставляется путь `certs/<имя>`, а настройки применяются, как обычно,
кнопкой «Сохранить и перезапустить». Принимается PEM до 1 МиБ; если ключ лежит в одном файле с сертификатом —
загрузите файл в поле «Сертификат», поле «Ключ» останется пустым.

Правки — во вкладке «Дополнительно → Сервер» или правкой файла. Если сервер не поднялся с новыми
настройками (порт занят, битый сертификат), прежние возвращаются автоматически и сервер перезапускается.

## Настройка DNS устройств

Колонка обращается к настоящим доменам Яндекса — именно они должны разрешаться в LAN IP
компьютера с эмулятором:

- `quasar.yandex.net` — HTTP backend
- `uniproxy.alice.yandex.net` — WebSocket (голос, состояние)
- `rpc.alice.yandex.net` — RPC (опционально)

Hosts на компьютере для этого недостаточно — нужна настройка DNS на роутере или устройстве.
Эмулятор DNS не меняет.

Часто DNS отдаёт компьютеру с эмулятором не только эти имена, а всё `*.yandex.net` — в том числе
стриминговые хосты музыки (`strm-*.strm.yandex.net`). Это нормально: хосты, не покрытые
сертификатом сервера, фронт TLS ведёт туннелем к настоящему серверу (см. ниже).

## Фронт TLS

Wildcard-сертификат `*.yandex.net` покрывает один уровень, поэтому колонка не может открыть TLS к
`strm-m9-136.strm.yandex.net` — рукопожатие рвётся, музыка не играет. Фронт читает SNI из
ClientHello до TLS: имя покрыто сертификатом (или SNI нет, или это литеральный IP или имя локальной сети) — соединение идёт в
эмулятор как раньше; иначе — слепой TCP-туннель к настоящему адресу хоста (A-записи у `front_dns`,
aiodns): настоящий TLS с настоящим сертификатом, содержимое эмулятору не видно. Адрес самого
сервера туннелем не используется (защита от петли). Реальный IP колонки сохраняется (таблица
соответствий, `dispatcher.client_ip`). События — в журнале сервера («Дополнительно → Лог»):
предупреждение о туннеле по домену, ошибки туннеля, старт фронта. Выключатель — `front: false`
или галочка в «Дополнительно → Сервер».

## TLS

Для HTTPS/WSS передайте PEM-сертификат (с цепочкой) и ключ параметрами `--cert` и `--key`.
Сертификаты и ключи в репозиторий не добавляются (см. `.gitignore`).

## Аутентификация

По умолчанию выключена (режим локальной лаборатории).

```powershell
python -m server_emulator.auth
```

Создаёт администратора и включает обязательный вход для панели и API. Роли: admin/user, сессии
HttpOnly+SameSite=Strict. Секреты провайдеров можно задавать ссылками `env:ИМЯ`. До включения входа
для удалённого доступа используйте SSH-туннель.

## Бэкап

Остановите сервер и скопируйте каталог `--state` (настройки, сценарии, пользователи, устройства, журналы).
