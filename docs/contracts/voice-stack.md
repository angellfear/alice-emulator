# Голосовой стек

## 1. Обзор
Для каждого сервиса (asr / tts / llm) активный источник выбирается в `settings["voice_stack"][service]` — это либо **пресет** `p:<id>`, либо **пакет** `k:<id>`. Применение (`apply`) записывает конфигурацию в `settings[stt|tts|model]` с ключом `"adapter"`. Конвейер (`Runtime.provider`, `recognize_stream`, `speech_stream`, `asr_streaming`, `tts_streaming`) вызывает адаптер, указанный в этом ключе. Профили устройств продолжают работать — они переопределяют те же настройки.

`apply` меняет общие настройки, поэтому UI голосовой вкладки перечитывает их после применения, а полное сохранение устаревшей копии формы сервер отклоняет по ревизии: `GET /api/settings` добавляет поле `_rev`, сохранение с чужой `_rev` отвечает 409 (форма перечитывает базу и сохраняет заново; запросы без `_rev` — внешние клиенты — сохраняются как раньше). Смена режима «Интеллект» — отдельный `PUT /api/intelligence`, сохраняющий только ключ `intelligence`: прежний полный PUT откатывал выбранный источник ASR и распознавание замолкало. Готовность источников показывает строка состояния в шапке панели — `GET /api/live` (см. `docs/architecture.md`, раздел «Переключение режима „Интеллект“ и строка состояния»).

### Режимы вывода ответа
`settings["voice_stack"]` кроме выбора источника держит два булевых ключа карточки «Синтез (TTS)» (не в `settings["tts"]`: её перезаписывает применение пресета/пакета):

| Ключ | По умолчанию | Смысл |
|---|---|---|
| `speak` | `true` | озвучивать ли ответ (синтез — сценарии, стандартные ответы, модель, пререндер отложенного ответа) |
| `card` | `true` | показывать ли карточку `simple_text` с текстом ответа |
| `speak_words` | `false` | знаки и числа произносить словами — только в тракте синтеза |

Режимы: озвучивать + карточка (по умолчанию) · только озвучивать (`card: false`) · не озвучивать, только карточка (`speak: false`). Ответа совсем без текста нет: выключенная озвучка делает карточку принудительно включённой — валидатор (`settings_service.validate`) поднимает `card` сам, UI держит галочку отмеченной и заблокированной. При выключенной озвучке синтез не вызывается вовсе, сервер пакета TTS при старте панели не поднимается (`autostart`), предзапекание звукового кеша не запускается; `VoiceResponse` остаётся пустым и `finalize` добавляет `tts_play_placeholder` (`channel: Dialog`) — ответ выглядит как беззвучные ответы настоящего сервера при `disable_output_speech`. Выключенная карточка действует поверх `spec["card"]` сценария: `simple_text` не добавляется ни для сценария, ни для модели, ни для стандартных ответов (сценарии с `card: false` не меняются). Выбор для сценарного движка передаётся в контексте — `ctx["settings"]["tts_speak"]` / `["tts_card"]` (собирает `runtime._scenario_context`).

**«Знаки и числа словами» (`speak_words`).** Многие TTS-движки не читают цифры и знаки; с включённой галочкой перед синтезом (оба движка — потоковый и batch — единая точка `audio_buffer.synthesize`; `synthesize_cached` применяет подготовку до вычисления ключа кеша, поэтому включение галочки не отдаёт старое озвучивание) текст проходит `spoken.spoken_words`. Числа — `num2words` (`>=0.5.14,<2`, LGPL), единицы согласует с числом `pymorphy3` («1 градус», «2 градуса», «5 и 11 градусов», «21 градус», «22 градуса»), знаки — единственная таблица `spoken._SIGNS` (RU/EN по языку ответа). Текст карточки и журнал остаются без изменений. Разметка `<speaker …>`/`<[domain …]>` не трогается — числа внутри тегов сохраняются (движок читает параметры разметки сам).

Порядок обработки куска текста (вне тегов): невидимые символы и неразрывные пробелы → группы разрядов («1 000 000» → одно число) → кавычки и эмодзи/декор удаляются → даты и версии «13.11.2026» (числа по отдельности) → «5/10» («пять дробь десять») → дроби ½ ⅓ ⅔ ¼ ¾ → время → диапазоны → числа с единицами → единицы без числа → степени ² ³ → таблица знаков.

| Вид | Пример → озвучка |
|---|---|
| Градусы | `20°` → «двадцать градусов»; `+2°` → «плюс два градуса»; `-5°`, `−5°` (U+2212) → «минус пять градусов»; `20°C` / `20 °С` → «… градусов Цельсия»; `21°F` → «двадцать один градус по Фаренгейту»; `2,5°` → «две целых пять десятых градуса» |
| Единицы при числе | `%` процент, `‰` промилле, `′` минута, `″` секунда, `мм рт. ст.` (миллиметр ртутного столба), `м/с`, `км/ч`, `гПа`, `мм`, `см`, `км`, `кг`, `м²`/`км²` («в квадрате»), `м³` («в кубе»); валюты `$ € £ ₽ руб.` ставятся после числа: `$100` → «сто долларов», `£` — «фунт стерлингов» |
| Диапазон целых | `10–15 °C`, `+2…+5°` (тире, длинное тире, многоточие) → «от десяти до пятнадцати градусов Цельсия»; дефис `10-15` не диапазон (телефоны, даты) |
| Время | `21:00` → «двадцать один час»; `7:05` → «семь ноль пять»; `7:30` → «семь тридцать» |
| Род числительного | 1 и 2 по следующему существительному: «одна минута», «две секунды», «двадцать одно окно» |
| Десятичные | `3,5`, `3.5` → «три целых пять десятых» |
| Дроби, степени | `½ ⅓ ⅔ ¼ ¾` («1½» → «один и одна вторая»), `² ³` без единицы → «в квадрате», «в кубе» |
| Эмодзи и декор | эмодзи, `★ ✓ • · ■ ▶ © ® ™`, стрелки кроме `→`, кавычки `« » „ “ ” "` — удаляются, не озвучиваются |
| Паузы | многоточие и тире остаются: движки читают их как паузу; `\|` → запятая; `_` → пробел |

Таблица `_SIGNS` (одиночные знаки; при числе `° % ‰ ′ ″ $ € £ ₽` читаются как единицы выше, здесь — запасной вид без числа): `>` больше · `<` меньше · `≥` больше или равно · `≤` меньше или равно · `≠` не равно · `=` равно · `≈`, `~` примерно · `±` плюс-минус · `+` плюс · `−` минус · `×` умножить на · `÷` разделить на · `^` в степени · `→` стрелка · `#` решётка · `№` номер · `§` параграф · `@` собака · `&` и · `*` звёздочка · `/` слэш · `\` обратный слэш · `$` долларов · `€` евро · `£` фунтов · `₽` рублей · `%` процентов · `‰` промилле · `°` градусов · `′` минут · `″` секунд. Не озвучивается и остаётся как есть: римские цифры, числа в составе слов и телефонных номеров.

## 2. Пресеты
**Файл:** `state/voice_stack/presets/<service>/<id>.json`
```json
{
  "id": "my-whisper",
  "service": "asr",
  "title": "Whisper local",
  "adapter": "openai",
  "values": { "url": "http://127.0.0.1:5013/v1/audio/transcriptions", "model": "base" }
}
```
UI «Добавить» → выбрать адаптер → «Заполнить как» (examples из адаптера) → создать. API-ключ маскируется значением `__KEEP__` (подставляется прежнее значение при сохранении). Миграция «Текущие настройки» создаёт пресет из имеющихся `settings[stt|tts|model]`, если источник не выбран.

## 3. Адаптеры — код
**Контракт модуля** (встроенные в `server_emulator/voice_stack/adapters/`, свои — в `server_emulator/state/voice_stack/adapters/<id>.py`, подхватываются без рестарта по mtime):
```python
TITLE = "Anthropic (Claude)"
DESCRIPTION = "..."
SERVICES = {
    "llm": {
        "title": "YandexGPT (Online)",          # необязательно: название сервиса вместо TITLE (адаптер на несколько сервисов)
        "description": "...",                    # необязательно: описание сервиса вместо DESCRIPTION
        "fields": [{"key": "api_key", "type": "password"}, {"key": "model", "type": "select", "options": [...]}],
        "defaults": {"url": "https://api.anthropic.com/v1/messages", "model": "claude-haiku-5-5", "temperature": 0.3},
        "examples": {"Groq": {"url": "https://api.groq.com/openai/v1/chat/completions", "model": "llama-3.3-70b-versatile"}}
    },
    "tts": {"voice_modes": ["preset", "baked"], "bake": {"seconds": [5, 120], "text": False}, "fields": [...], "defaults": {...}}
}
MATCH = {"llm": r"api\.anthropic\.com"}  # автоопределение по URL старых настроек

async def complete(runtime, config, payload) -> dict          # LLM: OpenAI chat → {"choices":[{"message"}],"usage"}
async def transcribe(runtime, config, audio, filename) -> str  # ASR: аудио целиком → текст
async def recognize_stream(runtime, config, chunks, fmt, on_partial) -> {"text"}  # ASR потоком (опц.)
async def speech(runtime, config, payload) -> (bytes, content_type)  # TTS: OpenAI Speech payload → Ogg Opus
def speech_stream(runtime, config, text) -> AsyncGenerator[bytes, None]  # TTS потоком (опц.)
def streams(config) -> bool                 # TTS: использовать speech_stream для этой конфигурации
async def synth_pcm(runtime, config, text) -> (np.ndarray float32, rate)   # TTS: PCM целиком для звукового кеша (необязательно)
async def voices(runtime, config) -> [{"value", "label", "lang", "gender"}]   # список голосов поставщика (необязательно)
async def bake_voice(runtime, config, audio, text) -> {"voice_id", "title"}   # запечь голос (необязательно)
async def unbake_voice(runtime, config, voice_id) -> None                      # удалить запечённый голос (необязательно)
```
`runtime.lifecycle.client_session()` — общий `aiohttp` клиент; `config` — копия настроек с полями пресета; `api_key` как есть (`env:VAR` раскрывает `auth.secret`).

**Транспорт LLM встроенных адаптеров** — LiteLLM (`litellm.acompletion`, телеметрия выключена —
панель локальный сервис): `openai.py` — провайдер `openai`, произвольный OpenAI-совместимый URL
из поля (база для litellm — адрес без `/chat/completions`; если адрес суффикса не имеет, он
передаётся как база целиком и litellm добавляет суффикс сам — итоговый адрес отличается, поле
должно быть полным адресом запроса из пресетов); `anthropic.py` — провайдер `anthropic`
(база — адрес без `/v1/messages`), конвертацию форматов делает litellm, счётчики usage адаптер
сводит к `{"prompt_tokens", "completion_tokens"}`. ASR/TTS и пользовательские адаптеры ходят
через общий `aiohttp`-клиент `runtime.lifecycle`; у LLM-адаптеров клиенты собственные у litellm
(официальные SDK под ним). Диапазон версий и исключения — в `pyproject.toml`.

**Модели по подписке** (без API-ключа, лимиты подписки): `chatgpt.py` — провайдер LiteLLM
`chatgpt` (бэкенд Codex CLI, ответы с инструментами). Вход — один раз в терминале:
`python -m server_emulator.voice_stack.login chatgpt [--state <папка>]` — вход по коду устройства
делает LiteLLM (ссылка и код в терминале), файл входа — `state/voice_stack/chatgpt/auth.json`,
токен обновляется сам. Код устройства требует человека, поэтому вход — отдельной командой, не из
сервера; без файла входа адаптер отвечает ошибкой с этой командой. Температуру модели с
размышлением не принимают — адаптер её не передаёт.

`claude.py` — Claude Pro/Max через Claude Agent SDK (готового провайдера подписки у LiteLLM
нет; SDK — официальный путь Anthropic, ходит через Claude Code). Конвейеру нужен один шаг модели,
SDK же ведёт свой цикл агента: инструменты запроса становятся инструментами SDK-сервера MCP
`alice` (свои инструменты Claude Code выключены, `tools=[]`), хук PreToolUse отвечает `defer` —
прогон останавливается, вызов приходит в `ResultMessage.deferred_tool_use` и уходит конвейеру как
`tool_calls`. История передаётся одной репликой-стенограммой (реплики, вызовы и результаты
инструментов), системные сообщения и `tool_choice` — системным промптом. Вход — токен
`claude setup-token` в поле пресета (`CLAUDE_CODE_OAUTH_TOKEN`), пусто — вход установленного
Claude Code. Настройки, CLAUDE.md и сессии пользователя не читаются и не пишутся
(`setting_sources=[]`, `--no-session-persistence`), рабочая папка — `state/voice_stack/claude`.
Каждый запрос запускает процесс Claude Code — ответ на секунды дольше, чем через API.

**Пример кастомного LLM адаптера** (`server_emulator/state/voice_stack/adapters/myllm.py`):
```python
TITLE = "My LLM"
DESCRIPTION = "OpenAI-совместимый"
SERVICES = {"llm": {"fields": [{"key":"url","type":"text"},{"key":"model","type":"text"},{"key":"api_key","type":"password"}], "defaults":{"url":"https://api.example.com/v1/chat/completions","model":"my-model"}}}
MATCH = {"llm": r"api\.example\.com"}

async def complete(runtime, config, payload):
    async with runtime.lifecycle.client_session().post(config["url"], json=payload, headers={"Authorization": f"Bearer {config['api_key']}"}) as r:
        return await r.json()
```

**Встроенные адаптеры:** см. таблицу «Поставщики» ниже.

**Уровень звука перед распознаванием:** микрофон колонки тихий (пик около −55 dBFS) —
`audio_gain.AutoGain` выравнивает уровень звука колонки перед ASR и детектором пауз.
Включение — настройка `settings["stt"].level` (`"yes"` по умолчанию, `"no"` — выключено,
галочка «Выравнивание уровня микрофона»): batch-путь (`audio_buffer.input_audio(..., level=...)`)
и детектор пауз эмуляции потока (`audio_stream.transcode(..., level=...)`); `deepgram` и
адаптер `stream` — без этой настройки (у `stream` своя — `normalize`). Сегменты эмуляции
распознаются уже выровненными.

**Эмуляция потокового режима для batch-STT** (`server_emulator/asr_pseudo_stream.py`): готового
потокового режима у локальных batch-движков нет (onnx-asr/GigaAM не умеют стриминг) —
`provider_manager` ветвит вызовы ASR: адаптер с `recognize_stream` (`stream`, `deepgram`) —
настоящий поток как есть; batch-адаптер с включённой настройкой `settings["stt"].pseudo_stream`
(галочка «Эмуляция потокового режима» в карточке ASR, видна только когда активный STT не
потоковый — `GET voice-stack` отвечает `streaming: true/false`) — детектор пауз Silero VAD
по ходу приёма звука. Фраза — вся речь от первого слова до паузы конца: кадры речи и пауз
между словами копятся в буфере целиком. Пауза между словами `stt.pseudo_partial_pause`
(0.2–2.0 с, умолчание 0.4) — вся накопленная фраза распознаётся тем же batch-STT (WAV через
`audio_buffer.input_audio`, `_transcribe_audio`), частичный AsrResult колонке несёт весь
текст фразы на этот момент и заменяет прежний частичный (AsrResult-шаблон тот же, что у
потокового пути `voice.py`); пауза конца фразы `stt.pseudo_end_pause` (0.5–5.0 с и больше
паузы между словами, умолчание 1.8) или закрытие микрофона — вся фраза распознаётся ещё
раз, финальный текст и STOP_RECORDING — колонка закрывает микрофон в конце фразы, а не по
тайм-ауту NO_SPEECH. Ключа нет, не число или вне диапазона — умолчание, без ошибки.
Шумовой всплеск короче `MIN_SPEECH_S` (0.25 с) сам не распознаётся, но его кадры остаются
во фразе — распознаются вместе со следующей речью. Фраза длиннее 20 с (лимит моделей):
текст окна 20 с фиксируется, буфер начинается заново, финал — зафиксированные окна плюс
текст последнего окна. Слово активации отбрасывается: реплика приходит отдельным логическим
потоком Ogg — BOS сбрасывает накопление, как у stream-адаптера. Модель VAD —
`silero-vad/silero_vad.onnx` установленного голосового
пакета (gigaam, sherpa-t-one ставят её вместе с движком), драйвер `onnxruntime>=1.20,<2`
в основных зависимостях (CPU, шаг 512 сэмплов 16 кГц — один вызов модели на кадр; вход модели —
576 сэмплов: 64 контекст прошлых + 512 новых, как в эталонном вызове `onnx_asr.models.silero`
этой сборки модели — без контекста вероятности около нуля на любой речи). Если колонка всё же
закрыла микрофон NO_SPEECH, а эмуляция накопила речь (конец фразы ещё не решён) — накопленное
уходит на полный ход распознавания (`voice.py`): финальный AsrResult и реплика, а не отмена
задачи — фраза не теряется. Невыполнимо (нет драйвера или модели) — честный откат на
распознавание целиком, причина один раз в журнале.

### Поля адаптеров и пакетов
Поле — `key`, `label`, `type` (`text` · `password` · `number` · `select` · `textarea` · `file`), `options`, `when` и метаданные для UI:

| Ключ поля | Значение | Как показывает UI |
|---|---|---|
| `"type": "password"` | токен, ключ, секрет | поле-пароль; значение не возвращается в API открытым (маска `__KEEP__`, пусто = оставить прежний), `env:VAR` работает |
| `"help"` | одна строка: где взять | подсказка под полем — только у полей, где без неё не обойтись |
| `"link"` | URL страницы получения ключа | ссылка «Получить ключ» рядом с названием поля |
| `"group": "advanced"` | редкий параметр | поле под кнопкой «Дополнительно» (свёрнуто по умолчанию, состояние хранится только в открытой странице) |
| `"required": true` | без значения не работает | звёздочка у названия; «Создать» / «Сохранить» / «Применить» подсвечивают пустое и не продолжают |
| `"options_from": "voices"` | список голосов с API поставщика | select с кнопкой «Обновить список»; адаптер даёт `voices()`; ошибка или адаптер без `voices()` — список `options` по умолчанию + сообщение |
| `"options_from": "gpus"` | видеокарты NVIDIA | как раньше (пакеты) |

Если список зависит от поля `engine` (Google TTS, Microsoft TTS), при смене движка UI запрашивает голоса заново. «Обновить список» передаёт адаптеру `config["refresh"] = True` (адаптеры кешируют список на 10 минут; `voices(runtime, config, refresh=False)`). Поле с `when` и `required` обязательно только пока видно: скрытые условием поля не подсвечиваются и не проверяются.

Метаданные проверяет `validate_fields` (неизвестные `group` и `options_from` отвергаются). У пакетов (`voice_stack/packages/*.json`) те же ключи: порт, потоки, приоритет, чекпойнт, шаги — `group: advanced`.

### Голос TTS: режимы
`"voice_modes"` у сервиса адаптера (`SERVICES["tts"]`) или у пакета — подмножество, в порядке показа:

| Режим | Подпись в UI | Смысл | Поля |
|---|---|---|---|
| `preset` | Встроенный голос | голос поставщика/модели | select голоса (`options` или `options_from: voices`), стиль/эмоция |
| `baked` | Свой голос (запечённый) | эталон обрабатывается один раз и хранится: у поставщика — созданный `voice_id`, локально — файл эмбеддинга (`.pt`); синтез потом без эталона | загрузка эталона и текст, «Запечь», статус «Запечён / Не запечён», «Удалить голос» |
| `clone` | Клонирование по эталону | эталон подставляется в каждый запрос | поле-файл эталона + текст |

Переключатель показывается, если режимов больше одного; единственный `baked`/`clone` — подписью над полями. Текущий режим — значение `voice_mode` (пресеты и параметры пакета; служебные `voice_mode`, `baked_voice_id`, `baked_voice_title` принимаются без объявления в `fields`). Поля режима — обычные поля с `"when": {"voice_mode": "clone"}`. Постоянный `voice_id` (ElevenLabs и т. п.) — это `baked`, не `clone`.

**Запекание у поставщика (пресет).** `SERVICES["tts"]["bake"]` — необязательные правила: `seconds` (допустимая длина эталона, по умолчанию 2–30 с) и `text: false` (текст эталона не нужен). `POST voice-stack-bake` (multipart: `meta` — `{service, adapter, values, id?, text}` и WAV `audio`) вызывает `bake_voice` и возвращает `{voice_id, title}`; UI кладёт их в `baked_voice_id` / `baked_voice_title` пресета и сохраняет. Эталон нигде не хранится. `POST voice-stack-unbake` вызывает `unbake_voice` (если есть) — UI очищает значения. Адаптер получает `config["voice_mode"]` и `config["baked_voice_id"]`.

**Клонирование (пресет).** Поле-файл адаптера (`type: file`, `when: {voice_mode: clone}`) загружается в сохранённый пресет: `POST voice-stack-preset-file?service=&id=&key=` (WAV, как у пакетов), хранится в `state/voice_stack/presets/<service>/<id>/<ключ>.wav`, путь попадает в `config[<ключ>]` при применении; наружу API путь не отдаёт — только `files`. Удаление пресета удаляет и эталон.

**Запекание у пакета.** `"bake": {"audio": "<поле-файл>", "text": "<поле текста>", "mode": "baked", "transcribe": true}`: сервер пакета запекает эталон при запуске (OmniVoice: `<эталон>.<sha1(WAV + текст)[:12]>.pt` рядом с WAV). «Запечь» = сохранить параметры, распознать пустой текст текущим ASR (кроме `"transcribe": false` — модели текст не нужен, как XTTS-v2), перезапустить сервер (`POST voice-stack-bake {package}`); статус — наличие файла эмбеддинга с актуальным хешем (`bake.baked`, `bake.name` в `GET voice-stack`). «Удалить голос» удаляет эталон и его `.pt` (`POST voice-stack-unbake {package}`). Вне режима `bake.mode` эталон серверу не передаётся (`OV_REF_AUDIO` пуст).
## 4. Пакеты
**JSON формат** (`voice_stack/packages/<id>.json`): все ключи из docstring модуля.
```json
{
  "id": "piper", "service": "tts", "title": "Piper", "order": 10,
  "requirements": {"gpu": false, "vram_gb": 0, "disk_gb": 0.2},
  "adapter": "openai",
  "config": {"url": "http://127.0.0.1:{port}/v1/audio/speech", "voice": "{voice}"},
  "fields": [{"key":"voice","type":"select","options":[...]},{"key":"device","type":"select","options":[{"value":"cpu"},{"value":"cuda"}]}],
  "defaults": {"device": "cpu", "port": 5014, "voice": "irina"},
  "server": {"script": "tools/builder_tts.py", "health": "/health", "env": {"TTS_THREADS": "{threads}"}},
  "platforms": {"windows": {"cpu": [{"pip": ["sherpa-onnx==1.13.8", "numpy", "aiohttp"]}], "cuda": [{"pip": ["sherpa-onnx==1.13.8+cuda", "numpy", "aiohttp"], "args": ["-f", "https://k2-fsa.github.io/sherpa/onnx/cuda.html"]}]}, "linux": {...}},
  "notes": {"linux": "..."},
  "models": [{"url": "https://.../{voice}.tar.bz2"}],   // .tar.bz2 / .tar.gz / .zip распаковываются (внутри — папка модели)
  "reinstall_on": ["device", "voice"],
  "depends": ["shared-id"]                                // необязательно: общие зависимости в <speech>/_shared/<id>
}
```
Шаг установки — `{"pip": [...], "args": [...]}` (pip в venv пакета), `{"uninstall": [...]}` (`pip uninstall --yes`: у onnx-asr `onnxruntime` и `onnxruntime-gpu` делят один каталог пакета, поэтому перед установкой любой из сборок обе удаляются) или `{"run": [...], "title": "..."}`. Плейсхолдеры: параметры запуска, `{dir}` — папка установки, `{python}` — python venv, `{tools}` — папка `tools/` проекта. Параметры запуска хранятся в `state/voice_stack/packages/<id>.json` — доступны до установки и переживают удаление. venv: `data/speech/<id>/venv`. Живой `/health` на порту = «запущен»; сервер, оставшийся после падения панели, находится и останавливается (см. «Жизненный цикл серверов»). TTS-сервер на `speech_common.tts_app` открывает порт только после загрузки и прогревающего синтеза (`warm_up`): первый запрос не платит за холодный старт движка (на CUDA — секунды, дольше ожидания озвучки `tts_wait_s`). Сбой прогрева запуск не отменяет.

**Поля параметров запуска:** `"when": {"device": "cuda"}` — поле видно только при этом значении другого поля; `"options_from": "gpus"` — список видеокарт NVIDIA из `nvidia-smi` (значение — индекс, уходит в `CUDA_VISIBLE_DEVICES`). Ключ `priority: "low"` запускает сервер с фоновым приоритетом (Windows `BELOW_NORMAL_PRIORITY_CLASS`, Linux `nice 10`); `threads` ограничивает потоки процессора. Сборка под CUDA работает и на процессоре — переключение cuda→cpu переустановки не требует. PID сервера пишется в `data/speech/<id>/server.pid`: «Перезапустить» останавливает и процесс, запущенный прошлым экземпляром панели.

**CUDA у пакетов.** Выбор `device: cuda` требует установки под видеокарту: перед `pip` установщик проверяет, что `nvidia-smi` видит карту; маркер `installed.json` хранит устройство установки. Пакет, установленный под `cpu`, при `device: cuda` не запускается (`LocalSpeech.start` → `ValueError` «Нажмите «Переустановить»»), а `outdated` показывает кнопку «Переустановить». Пакеты на onnx-asr (gigaam, parakeet) ставят `onnxruntime-gpu[cuda,cudnn]` + `nvidia-cublas-cu12` (CUDA и cuDNN из pip, системный CUDA Toolkit не нужен; драйвер NVIDIA 525+) и завершают установку шагом `tools/onnx_cuda.py` — реальная сессия onnxruntime на файле модели в том же venv: если провайдер CUDA не загрузился, установка падает с причиной, а не «успешно». Тот же `onnx_cuda.problem()` вызывает сервер при запуске с `ASR_DEVICE=cuda`: в `server.log` и в карточке пакета — какой драйвер, какая сборка onnxruntime стоит и что делать (старый драйвер, сборка только для CPU, обе сборки одновременно, не загрузились cuDNN/cuBLAS). Пакеты на torch (f5-tts, espeech и др.) берут колёса из индекса `https://download.pytorch.org/whl/cu126` (драйвер с CUDA 12.6+).

`sherpa-t-one` (пакет `sherpa-onnx`, C++ со своим вшитым onnxruntime — не `onnxruntime-gpu`) ставит под CUDA версию с тегом `+cuda12.cudnn9` (не `+cuda` — это старый тег под CUDA 11/cuDNN 8, с CUDA 12 он не грузится) и те же `nvidia-*-cu12` колёса (`cuda-runtime`, `cublas`, `cudnn`, `cufft` — ровно то, что статически импортирует `onnxruntime_providers_cuda.dll` этой сборки) отдельным шагом `pip`, так как `sherpa-onnx` их не тянет сам. `speech_common.preload_cuda_libs()` добавляет их каталоги `bin/` в путь поиска DLL (`os.add_dll_directory`, Windows) до импорта `sherpa_onnx` (`tools/builder_asr.py`) — без этого `onnxruntime_providers_cuda.dll` сервера не находит свои зависимости и ONNX Runtime падает на процессор.

**Поле-файл** (`"type": "file"`, F5 — эталон голоса): загрузка `POST voice-stack-file?id=&key=` телом WAV; сервер проверяет RIFF/WAVE, PCM или float, 1–2 канала, 8–96 кГц, 2–30 с, ≤15 МБ. Один файл на поле: `state/voice_stack/packages/<id>/<key>.wav` (замена перезаписывает), путь пишется в параметр; `GET` — прослушать, `DELETE` — удалить. Загрузка в применённый пакет перезапускает сервер.

### Жизненный цикл серверов
Код: `voice_stack/lifecycle.py` (`Lifecycle`), `voice_stack/processes.py`; процессы — через `psutil`.

**Применение источника** (`VoiceStack.apply`, кнопка «Применить») — единый план: 1) нужные новой конфигурации пакеты — применённые источники других сервисов и выбранный (сервер TTS при выключенной озвучке не нужен, если его не применяют прямо сейчас); 2) все остальные работающие серверы пакетов останавливаются, в том числе поднятые прошлыми запусками панели и поставленные вручную («Запустить»); 3) для каждого — проверка, что порт перестал слушаться и (для видеокарты NVIDIA, `nvidia-smi`) процессы пропали из списка вычислительных приложений; 4) запись `settings`; 5) запуск пакета и ожидание `/health` (до 90 с; процесс жив, но ответа нет — предупреждение, умер — ошибка с хвостом `server.log`). Не удалось остановить или порт занят чужим процессом — применение прерывается до записи настроек: источник не меняется.

**Как находятся процессы пакета** (чужие не затрагиваются): процесс из реестра панели (`LocalSpeech.processes`); PID из `<папка пакета>/server.pid` (проверяется по командной строке, устаревший файл удаляется — переиспользованный PID чужого процесса не убивается); сканирование всех процессов — интерпретатор из `<папка пакета>/venv` (кроме `-m pip|venv|ensurepip`, то есть не установка) либо скрипт `server.script` пакета с рабочим каталогом в папке пакета. Пакет с идущей установкой пропускается. Останавливается дерево: на Windows `venv\Scripts\python.exe` — пускатель, сервер — его дочерний процесс, рабочие процессы — внуки. Мягкое завершение (5 с), затем `kill`, затем повторное ожидание; пережившие — ошибка шага. Чужой процесс на порту не убивается: шаг «порт» завершается ошибкой с именем и PID.

**Остановка панели** (`Runtime.close` → `VoiceStack.shutdown`) — тот же поиск и остановка всех серверов, включая осиротевшие. Второй экземпляр панели со своими движками — `ALICA_SPEECH_DIR` (папка вместо `data/speech`): иначе экземпляры видят и останавливают процессы друг друга.

**Папка пакетов.** `voice_stack.resolve_speech_dir(state)` (`speech_dir_from_config` по уже загруженному `server.json`) выбирает папку по приоритету: окружение `ALICA_SPEECH_DIR` (второй экземпляр панели/тесты) > настройка «Папка голосовых пакетов» в «Дополнительно → Сервер» (`server_config.py`, ключ `speech_dir`, относительный путь — от корня проекта) > `data/speech` внутри проекта по умолчанию. Настройка хранится в `state/server.json`, применяется перезапуском сервера (как адрес и порты), пустое значение — путь по умолчанию. `VoiceStack` читает её один раз при создании (`runtime.directory` → `server.json` рядом). Смена пути не переносит и не удаляет файлы по прежнему пути: `PUT /api/server` возвращает предупреждение в `warnings`, если по новому пути пакетов нет — переустановка потребуется.

**Ход применения.** `POST /voice-stack-apply-plan` → `{stop: [{id, title, pid, pids, port}], start, keep}`; `POST /voice-stack-apply` с `background: true` → `{job}`, `GET /voice-stack-apply?job=` → `{state: running|ok|warn|error, summary, steps: [{kind: stop|port|gpu|start|info, title, pid?, status: run|ok|warn|fail, detail}]}` (опрос 0,4 с; отдельного канала событий нет, как и у установки пакета). Одновременно идёт одно применение. UI (`ui/voice_stack_local.js`, `window.voiceApply`): план пуст (нечего останавливать и запускать) — применение без окна; иначе модальный `<dialog>` с шагами «Останавливается / Порт освобождается / Видеопамять освобождается / Запускается», итогом и кнопкой «Закрыть» (активна после завершения; Esc до конца работы не закрывает).

### Установлено локально
Код: `voice_stack/installed.py` (`Inventory`), блок под карточками вкладки «Голосовой стек». Каталоги `<speech>/<id>/` (окружение, модели, лог) — пакеты; каталог без описания пакета (удалён сам пакет или выключено расширение) — «без описания»; `<speech>/_shared/<id>/` — общие зависимости, пакет перечисляет их в `"depends": ["<id>", …]` (латиница/цифры/`._-`). Статус пакета: «Используется» — применён в `settings["voice_stack"]` или сервер работает, «Идёт установка», иначе «Не используется». Общая зависимость нужна, пока на неё ссылается хоть один установленный пакет.

Очистка (`POST /voice-stack-clean`: `{ids}` или `{all_unused: true}`) удаляет каталог неиспользуемого пакета и общие зависимости, на которые после этого не ссылается ни один установленный пакет; зависимость оставшегося пакета остаётся. Используемое сервер отказывается удалять (400), как бы ни была вызвана очистка; параметры запуска (`state/voice_stack/packages/<id>.json`) сохраняются. Размеры считает фоновый поток (обход каталога без ссылок), результат кешируется на 10 минут с ключом — отметка `installed.json`, поэтому установка и очистка пересчитывают сами; пока размер неизвестен, `GET /voice-stack-installed` отдаёт `size: null` и `computing: true` (UI переопрашивает раз в 2 с). Ответ: `{items: [{id, kind: package|orphan|shared, title, service, size, status, reason, removable, frees}], total, reclaimable, reclaim_ids, computing}`.

Облачные ASR здесь распознают фразу целиком (REST): потоковые режимы Яндекса, Сбера и T-Bank доступны только по gRPC (нужен `grpcio`, в зависимости не добавляется). TTS отдаётся сырым PCM и кодируется в Ogg Opus конвейером (`speech_stream`, `synth_pcm` для звукового кеша).

**Яндекс.** SpeechKit REST v1 (`stt:recognize` ≤30 с и ≤1 МБ, `tts:synthesize` lpcm), заголовок `Authorization: Api-Key`; YandexGPT — OpenAI-совместимый интерфейс, модель `gpt://<каталог>/<модель>`, `Bearer` и `OpenAI-Project`. Эмоция отправляется, только если её поддерживает выбранный голос.

**Сбер.** OAuth `POST /api/v2/oauth` (`Basic <ключ>`, `RqUID` — uuid4, `scope=SALUTE_SPEECH_<тип>` или `GIGACHAT_API_<тип>`): `access_token` живёт 30 минут и кешируется в памяти до истечения (за минуту до конца — новый); отозванный раньше срока токен (401) обновляется один раз. Серверы подписаны сертификатом НУЦ Минцифры: в «Дополнительно» указывается путь к корневому сертификату (`ca_bundle`) либо отключается проверка (`verify: off`, небезопасно). GigaChat: инструменты OpenAI ↔ `functions` / `function_call`.

**T-Bank.** JWT HS256 (`kid` — API-ключ, подпись — секретный ключ из base64url, `aud` = `tinkoff.cloud.stt` / `tinkoff.cloud.tts`, срок 10 минут, кеш до истечения), REST `POST /v1/stt:recognize` и `/v1/tts:synthesize` (JSON, base64).

## Звуковой кеш
Раздел «Звуковой кеш» (бывшие «Стандартные ответы»): фразы — включённые стандартные ответы и всё, что уже озвучивалось через кеш (сценарии), индекс `state/tts_cache/index.json`. Кеш работает, если синтез отдаёт PCM (`Runtime.get_tts()` → `voice_stack.PcmTTS`, адаптер с `synth_pcm` и `pcm_f32le`/`wav`); ключ файла — движок + URL + модель + голос + текст. Стандартные ответы озвучиваются через кеш. `POST sound-cache-regenerate` пересинтезирует все фразы текущей моделью в фоне; `GET sound-cache` — `{engine, entries[{text, source, status}], job{total, done, errors, state}}`, статус фразы: missing (серый) · pending/running (жёлтый) · cached (зелёный) · error.
Фразы сценариев (без `{{переменных}}`) попадают в список сами; у записи `name`/`id` источника (`builtin` — встроенный сценарий), иконка правки открывает сценарий в редакторе с выделенной фразой (`window.openScenarioPhrase`), у стандартного ответа — модальный редактор (`window.openReplyEditor`, ui/replies.js). Реплика всегда озвучивается одной фразой (куски не склеиваются): фраза без переменных — из кеша целиком, с подставленными значениями — один запрос синтеза мимо кеша. Статические фразы, ушедшие из сценариев/ответов, удаляются из кеша при сохранении настроек; старые записи значений (`dynamic` в индексе) удаляются там же и при смене `settings.tts` (`TtsCache.drop_dynamic`).

**F5-TTS на Windows:** torchaudio ≥2.9 читает аудио через torchcodec (нужны DLL FFmpeg); `tools/f5_tts_server.py` подменяет `torchaudio.load` чтением через soundfile — эталон должен быть WAV/FLAC.

**Статусы:** `absent` / `installing` / `running` / `starting` / `stopped` / `error` / `unsupported`. «Переустановить» доступно, когда изменились ключи из `reinstall_on`.

**Пробы статуса:** состояния всех пакетов собираются параллельно, проба `/health` в статусе — с коротким тайм-аутом (0,4 с): сервер занят распознаванием/синтезом или грузит модель — вкладка не ждёт длинную пробу, процесс жив — статус `starting` до следующего опроса (UI опрашивает каждые 1,5 с, пока есть installing/starting). Длинный тайм-аут (1,5 с) остаётся у проверок готовности после запуска (`start`/`wait_ready`).

**Сбой установки:** карточка показывает шаг и последнюю строку вывода (`job.error`); полный
вывод упавшего шага сохраняется в `<пакет>/install.log` и в `detail` записи журнала сервера
(source=ws, `journal_detail` — stage/output), сообщение журнала остаётся одной строкой.

### Эталон голоса и запекание (OmniVoice)
Поле-файл (`type: file`) меняется только загрузкой/удалением файла; форма путь не перезаписывает. Новый файл не перезапускает сервер сразу — пакет помечается, и «Сохранить настройки» перезапускает работающий сервер. Если у поля есть `transcribe_to`, а текст пуст, при сохранении он распознаётся текущим ASR. Сервер OmniVoice запекает эталон один раз (`create_voice_clone_prompt` → `<поле>.<хеш>.pt` рядом с WAV; новый эталон или текст — новое запекание) и синтезирует с `voice_clone_prompt`; `instruct` применяется только без эталона, шаги — `num_step`. Удаление эталона удаляет и его `.pt`. Режим голоса виден в статусе пакета (`state.voice` из `/health`).
