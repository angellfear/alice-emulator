# Медиа и громкость на штатных механизмах колонки

Код: `server_emulator/media_directives.py`.

## Обзор

Управление плеером и громкостью директивами настоящего сервера. Плеер подробно — `player.md`.

## Плеер

Своей медиатеки у эмулятора нет: «включи музыку/сказку/песню» в эмуляции остаётся
без обработчика — эти фразы отвечает настоящий сервер Яндекса (в гибридном маршруте WS
целиком эмулируется, поэтому необработанные медио-реплики видны как «Без ответа»).
Эмулятор управляет колонкой по образцам: «стоп/пауза/подожди» — директивы настоящего
сервера без речи (`server_emulator/media_directives.py`: `divui_hide_view` +
`draw_animation_directive` (S3 `animations/player_pause`) + `player_pause` + `clear_queue`,
сценарий `device.player.pause`); состояние плеера читается из запроса колонки
(capability 46, `station_state`, SDK `ctx.player`); колбэки `HollywoodMusic`
(`music_thin_client_on_started/on_stopped`, `@@mm_stack_engine_get_next`) — тихий
`callbacks.ack`, как отвечал сервер. Контракт — `docs/contracts/player.md`.

## Громкость

Установка уровня голосом («громкость два/на семь/на 50») — **тихий** ответ по образцу
журнала (x3): `sound_set_level{new_level, new_percent_level}` + `tts_play_placeholder`,
без речи и карточек; процент = level·100/MaxLevel, шкала — из состояния колонки
(capability 23 `TVolumeCapability`, `station_state`, SDK `ctx.volume`). Своего учёта
громкости на сервере нет. «Громче/тише/выключи звук/на всю» — ответных образцов фраз в
журнале нет (шаги уровня наблюдались только как проводной Push из приложения), сохранён
прежний путь `device.push` — БЛОКЕР, нужна запись. Режимы подсветки («ночник/свеча/лава»)
и «выключи через …» (таймер сна) в журнале отсутствуют — БЛОКЕР, кода нет. Подсветка при
ответе: диалоговые ответы настоящего сервера (x1330) не несут `draw_led_screen`/
`draw_animation` — только `tts_play_placeholder`; анимации бывают в контекстах информеров
и эмоций LED, эмулятор повторяет именно их.
