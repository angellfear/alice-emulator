# Возможности колонки: объявление, запись, чтение

Код: `server_emulator/capabilities.py` (правило записи, чтение, наблюдатель),
`server_emulator/station_state.py` (разбор объявления), `server_emulator/identity.py`
(хранение в `state` устройства), `server_emulator/ui/users.js` (карточка состояния).
Тесты: `tests/test_capabilities.py`.

## Источник

Колонка сама объявляет возможности в каждом запросе — `Request.EnvironmentStateRaw`
(`NAlice.NAliceApi.TEnvironmentState`), оба пути соединения (Quasar и aapi) несут один
и тот же кадр:

- `Endpoints[].AnyCapabilities[]` — `CapabilityType` (enum `NAlice.TCapability.ECapabilityType`)
  + `RawCapability` (тело `NAlice.T…Capability`);
- `Endpoints[].Capabilities[]` — `google.protobuf.Any` с `type_url` `NAlice.T…Capability`.

Короткое имя — из имени типа без `NAlice.T` и `Capability` (`Alarm`, `Animation`,
`SmartHomeClientView`); имена enum вне шаблона `…CapabilityType` (`ThermostatType`,
`AccessibilityVoiceControlType`) пробуют вариант без хвоста `Type`. Типа нет в схемах —
имя по номеру (`#312`) без параметров, разбор не падает. Параметры — тело возможности
(`Meta`/`Parameters`/`State`) как dict (`MessageToDict`); они живые (яркость, плеер),
набор имён — стабильный.

## Запись

Наблюдатель AAPI-событий `TextInput`/`VoiceInput` (встроенный, `capabilities.observe`)
включается вместе с реестром идентичностей. Состав набора сравнивается по именам, без
разбора тел; изменился — тела разбираются и пишется
`device.state.capabilities = {ts, items: {имя: параметры}}`.

Правило (по журналам объявлений станции 2026-11-11…15: у одной колонки наборы
68 / 67 / 33 имени — 67 и 33 являются подмножествами полного 68):

- объявление-подмножество хранимого набора **не затирает** полный (сокращённые
  объявления — не признак потери возможности);
- изменился состав (появились имена вне хранимого) или хранилище пусто — набор
  заменяется целиком вместе с параметрами;
- запрос без состояния (`EnvironmentStateRaw` пуст) ничего не меняет;
- идентичный состав — записи нет (объявление идёт в каждом запросе).

Серийник берётся из самого объявления (`Endpoints[0].Id`), запись состояния —
под общим замком runtime (как fetch_state). Наблюдатель в выборе обработчика
не участвует (всегда `False`) и колонке не отвечает; сбой записи — warning.

## Чтение

Тонкий модуль, своих таблиц нет — читает `device.state.capabilities`:

| Функция | Ответ |
|---|---|
| `capabilities.names(device)` | отсортированный список коротких имён |
| `capabilities.has(device, name)` | объявлена ли возможность |
| `capabilities.params(device, name)` | `{Meta, Parameters, State}` или `{}` |
| `capabilities.announced_at(device)` | unix ts записи объявления, 0 — объявления нет |

Нет объявления — возможность «не заявлена»: потребители скрывают разделы, своих
таблиц по платформе нет (платформа остаётся только для того, что колонка не
объявляет: модель и картинка в UI, `STATION_TYPES` умного дома, путь Quasar-конфига).

Потребитель — умный дом: пуш списка устройств `set_iot_user_info` уходит только
колонкам, объявившим `LocalIoT`; первое объявление `LocalIoT` — пуш этой колонке
сразу, не дожидаясь изменения реестра (кому и когда — [smart-home.md](smart-home.md)).

## API и UI

Возможности едут наружу внутри `device.state` — `/emulator/api/identities` (GET),
отдельного API нет. Вкладка «Устройства»: карточка состояния (кнопка «Опросить»)
показывает раздел «Возможности» со списком имён и временем объявления.

## Инварианты

- Возможности колонки — только из её объявления; догадок по платформе нет.
- Наблюдатель не меняет ответ колонке и не ломает разбор чужого/битого кадра.
- Сокращённое объявление — подмножество; полный набор не забывается.
